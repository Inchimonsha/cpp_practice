# Разбор: ex04 — Event Log

## Как решать задумано

Журнал — это `std::vector<std::string>`. Все операции над ним — «чистые»
функции `shared/`; REPL только разбирает команду и вызывает их.

## Ключевые решения

### 1. `string_view` в параметрах, `vector<string>` при хранении

- чтение строки и префикса — `std::string_view` (нет копий);
- владение событиями — только `std::vector<std::string>` (контейнер с расширением
  объясняется в th05);
- `push_event` копирует вход в `std::string` — единственное место копии,
  и это необходимо для владения данными.

### 2. Поиск через `find` и `npos`

`count_matching` использует `find(fragment) != std::string::npos` — это
единственный надёжный способ понять «фрагмент есть».

### 3. REPL без дублирования логики

Команды `count`/`filter`/`stats` напрямую вызывают функции `shared/` —
в REPL нет собственных подсчётов. Поэтому логику можно тестировать без
консоли.

### 4. Разбор команды как «мини-DSL»

- `find(' ')` делит строку на команду и аргумент;
- `string_view` на подстроки строки `line` — безопасно, т.к. `line` живёт в
  теле цикла (область видимости — th03).

## Как выглядит эталонная схема

```
while running:
    line = read_line()
    cmd = cmd_of(line); arg = arg_of(line)
    cmd:
      "add"    -> push_event(log, arg)
      "count"  -> print count_matching(log, arg)
      "filter" -> for e in filter_prefix(log, arg): print e
      "stats"  -> print log.size(), average_length(log)
      "quit"   -> running = false
      else     -> print_help()
```

## Распределение ответственности

| Слой | Ответственность | Где |
|---|---|---|
| `shared/` | «чистая» логика журнала | event_log.hpp/.cpp |
| `main.cpp` | REPL, ввод-вывод, разбор команд | solution/main.cpp |
| `tests/` | контракты функций и граничные случаи | test_event_log.cpp |

## Оценка решения (критерии)

- [ ] Пять функций реализованы по контракту.
- [ ] Тесты покрывают: пустой журнал, пустой префикс, регистр, порядок
      при фильтрации.
- [ ] REPL толерантен к пустым строкам и неизвестным командам.
- [ ] `-Wall -Wextra` чисто; нет копий журнала в логике.
- [ ] Читаемость: имена в стиле курса, параметры-строки — `string_view`.

## Частые недочёты

- сравнение `find(...) == -1` вместо `npos`;
- «подсчёт» внутри REPL вместо вызова `count_matching`;
- `arg` строится при `space == npos` → `substr` за концом строки (UB);
- регистрозависимость в `filter` (ожидается по умолчанию);
- `average_length` не проверяет пустой журнал → деление на 0.

## Что оцениваем как «отлично»

- `starts_with` реализован без копий и используется в `filter_prefix`;
- REPL написан настолько тонко, что логика журнала тестируется без него;
- решение проходит `ctest -R ex04` зелёным.
