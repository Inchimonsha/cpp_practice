# ex04 — Event Log: постановка задачи

## 1. Название

«Event Log» — журнал игровых событий: хранить строки, искать по подстроке,
фильтровать по префиксу, считать статистику. Консольный REPL-интерфейс.

## 2. Уровень сложности

★★★☆☆.

## 3. Примерное время выполнения

2–4 часа.

## 4. Цели

- закрепить `std::vector<std::string>` и работу с ним (th05);
- закрепить `std::string` и `std::string_view` (th06);
- написать «мини-DSL» для REPL: разобрать команду и аргументы;
- понять, где бродит копия, а где — только «окно» на данные.

## 5. Какие знания закрепляются

- `push_back`/`size`/`reserve`; range-for;
- `find`/`substr`; `npos`;
- `string_view` как параметр без копий;
- обработка ввода команд в цикле.

## 6. Какие навыки нарабатываются

- парсинг строки команды вручную (без сторонних библиотек);
- проектирование «чистых» функций журнала;
- тестирование поисковых функций на граничных случаях.

## 7. Связанные теоретические темы

- [th05 — Массивы и контейнеры](../../theory/th05_arrays_containers/);
- [th06 — Строки](../../theory/th06_strings/).

## 8. Постановка задачи

Реализуйте библиотеку журнала (`shared/`) и REPL:

- `push_event(log, event)` — добавить событие в конец журнала;
- `count_matching(log, fragment)` — сколько событий содержат `fragment`;
- `filter_prefix(log, prefix)` — события, начинающиеся с `prefix`;
- `average_length(log)` — средняя длина строк журнала (0 для пустого);
- `starts_with(s, prefix)` — вспомогательный предикат.

REPL поддерживает команды: `add <текст>`, `count <подстрока>`,
`filter <префикс>`, `stats`, `quit`.

## 9. Функциональные требования

1. `add` добавляет событие в конец журнала.
2. `count` выводит число событий, содержащих указанную подстроку.
3. `filter` выводит все события, начинающиеся с префикса (по одному в строку).
4. `stats` выводит число событий и среднюю длину строки.
5. `quit` завершает REPL; пустая или неизвестная команда — подсказка.
6. Поиск по подстроке — с учётом регистра (простой вариант).

## 10. Нефункциональные требования

1. C++20, только стандартная библиотека.
2. Логика — в `shared/` по контракту `event_log.hpp`.
3. Каждая функция покрыта тестом (включая пустой журнал и пустой префикс).
4. Без предупреждений, без ручного `new/delete`.
5. `string_view` в параметрах «чтения»; хранение — только в `std::vector`.

## 11. Ограничения

- Регистронезависимость можно добавить только как расширение (в
  «Возможные расширения»), по умолчанию сравнение с учётом регистра.
- Без сторонних библиотек; ввод-вывод — только в `main.cpp`.

## 12. Необходимые инструменты

- компилятор C++20 (конфигурация курса из th01);
- `cmake`, `ctest`.

## 13. Подготовка

1. Прочитайте `task.md` полностью.
2. Изучите `shared/include/ex04/event_log.hpp` — контракт.
3. Откройте `starter/main.cpp` — TODO с разбором команд.

## 14. Подсказки

- Разбор команды: найдите первый пробел — `line.find(' ')`; левая часть —
  команда, правая — аргумент (`std::string_view`).
- `filter` использует `starts_with`; `count` — `find(fragment) != npos`.
- Не забывайте про `npos`: `find` вернёт его, когда фрагмента нет.

Подробные подсказки по уровням — в `hints.md`.

## 15. Самопроверка перед сдачей

- [ ] Программа собирается без предупреждений.
- [ ] `add`, `count`, `filter`, `stats`, `quit` работают.
- [ ] `count` для отсутствующей подстроки → 0.
- [ ] `filter` для пустого префикса выдаёт весь журнал.
- [ ] `average_length` для пустого журнала → 0.
- [ ] `ctest` зелёный.

## 16. Критерии оценки

Полный разбор — в `review.md`. Ключевое:

- корректность контрактов пяти функций;
- REPL не падает на «плохих» строках;
- отсутствие лишних копий (string_view/const&);
- тесты на граничные случаи.

## 17. Возможные расширения
