# Разбор решения: ex01 — Hello, Game Window

## 24. Разбор решения

Эталонное решение в `solution/main.cpp` — намеренно минималистичное: окно,
цикл, ввод, время. Ключевые решения:

1. **Цикл = события → обновление → отрисовка.** Такой порядок стандартен для
   игровых циклов: сначала «перевариваем» очередь событий, затем двигаем мир с
   учётом времени, затем рисуем.
2. **`delta time` для движения.** Скорость задана «в пикселях в секунду»,
   поэтому расстояние в кадре = `velocity * speed * dt`. Это делает движение
   независимым от FPS — цель проверяется тестом «медленно/быстро другое» в
   `ex01_tests`.
3. **`FpsCounter` вне `main.cpp`.** Сглаживание EMA — нетривиальная логика;
   её можно и нужно тестировать. Побочный эффект обучения: первое знакомство
   с разделением симуляции и визуализации (глубже — th34).
4. **`isKeyPressed` и события** — два разных механизма ввода: опрос
   (polling, в рамках кадра) и события (queue, дискретные действия).
   В решении использован опрос — он естественен для непрерывного движения.
   События — для дискретных действий (закрытие, пауза). Сравнение подходов —
   в th23.

Альтернативы, которые допустимы при соблюдении критериев:

- движение через события `KeyPressed/KeyReleased` и флаги «зажато/отпущено»;
- `sf::CircleShape` вместо прямоугольника;
- расчёт FPS по сумме кадров за секунду (без сглаживания, «прыгает»).

## 25. Идеи для рефакторинга

- **Структура `WindowConfig`**: `{width, height, title, framerate_limit}` —
  первый шаг к управляемой конфигурации (th33).
- **Функция `run()`**: вынос цикла в функцию с параметрами-коллбеками обновления
  и отрисовки — предтеча паттерна «game loop» (th28).
- **Слои**: отделить физическую логику движения от SFML (см. ex18, th28).
- **Заголовок FPS**: вынести форматирование в отдельную функцию.

## Вопросы для code review

Краткая анкета для ревьюера чужого решения:

- Учтён ли `dt` во всех местах, где движение зависит от времени?
- Не пересоздаётся ли `sf::Clock` на каждом кадре?
- Обработаны ли `sf::Event::Closed` и `Escape`?
- Сглажен ли FPS или «дрожит» на 60/144 Гц?
- Есть ли «магические числа»?
- Компилируется ли с `-Wall -Wextra` без замечаний?

## 26. Связь с реальной разработкой

Каркас из этого задания повторяется в каждом 2D-проекте курса и в индустрии
(упрощённо): движки оборачивают «окно + цикл + ввод + время» в ядро.
Независимость от FPS и тестируемость логики — это то, что отличает академические
примеры от продуктового кода. Разбор счётчиков времени и FPS как «прибора» для
оценки производительности продолжится в th50 и ex34.
