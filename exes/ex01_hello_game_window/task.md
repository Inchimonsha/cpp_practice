# ex01 — Hello, Game Window: постановка задачи

## 1. Название

«Hello, Game Window» — первое практическое задание курса: открыть окно
библиотеки SFML, запустить игровой цикл, обработать ввод и счёт времени.

## 2. Уровень сложности

★☆☆☆☆ — базовое.

## 3. Примерное время выполнения

1–2 часа (включая чтение постановки и самопроверку).

## 4. Цели

- собрать и запустить программу с графическим окном на SFML;
- понять структуру игрового цикла (обработка событий → обновление → отрисовка);
- познакомиться с `delta time` и счётчиком FPS;
- привыкнуть к разделению «логика / рендеринг» на простом примере.

## 5. Какие знания закрепляются

- жизненный цикл сборки программы (th01);
- событийная модель SFML 3 (события как `std::variant`);
- игровой цикл и его составные части;
- `sf::Clock` для измерения времени.

## 6. Какие навыки нарабатываются

- чтение документации SFML;
- запуск программы с окном и её корректное завершение;
- базовое тестирование логики без графики.

## 8. Постановка задачи

Напишите программу на C++20 (SFML 3.1.0), которая:

- создаёт окно 800×600 с заголовком `Hello, Game Window!`;
- запускает игровой цикл до закрытия окна (кнопка окна или клавиша `Esc`);
- рисует на цветном фоне прямоугольник, который движется стрелками
  клавиатуры;
- показывает текущий FPS в заголовке окна.

Разрешается начинать с каркаса из `starter/`.

## 9. Функциональные требования

1. Окно 800×600, заголовок `Hello, Game Window!`.
2. Игровой цикл обрабатывает события (закрытие, `Esc` → закрытие окна).
3. Прямоугольник (например, 50×50, зелёный) движется по горизонтали и
   вертикали стрелками.
4. Скорость движения учитывает `delta time` (одинакова на разных FPS).
5. В заголовке окна отображается текущий FPS.
6. Фон — тёмный цвет (например, `sf::Color{30, 30, 30}`).

## 10. Нефункциональные требования

1. Код компилируется как C++20 без предупреждений (`-Wall -Wextra`).
2. Логика счётчика FPS вынесена в `FpsCounter` (заголовок + реализация в
   `shared/`), тестируется без SFML.
3. Нет ручного `new`/`delete`.
4. Код читаемый: осмысленные имена, небольшие функции.
5. Константы (размер окна, скорость) вынесены в константы.

## 11. Ограничения

- Только SFML (без прочих библиотек); SFML-часть — только в
  `starter/main.cpp` / `solution/main.cpp`.
- Код запуска окна и игровой цикл — в одном файле `main.cpp` (детальное
  разделение на классы — следующий уровень, см. ex18).
- `FpsCounter` — единственный класс, который можно добавлять в `shared/`.

## 16. Примерный план решения

1. Получите зависимости (`python tools/fetch_deps.py`).

## 18. Критерии готовности

- `ex01_solution` собирается и запускается: открывается окно, движется
  прямоугольник, заголовок показывает FPS, закрытие работает;

## 19. Критерии проверки качества

| Критерий | Описание |
|---|---|
| Корректность | движение и FPS корректны |
| Скорость не зависит от FPS | при 30 и 60 FPS прямоугольник проходит то же расстояние |
| Чистота | FpsCounter отделён от окна, нет глобального состояния |
| Стиль | имена, константы, без магических чисел |
| Проверка ресурсов/ошибок | окно создано без явных исключений |

## 20. Типичные ошибки

- событие закрытия проверяется как `if (event == sf::Event::Closed)` — в SFML 3
  события это `std::variant`, сравнение не скомпилируется;
- движение выполняется без `delta time` — «газ на FPS»;
- `sf::Clock::restart()` вызывается не каждый кадр;
- `FpsCounter` пересчитывает FPS на каждом кадре, а не сглаживает;
- окно «не закрывается» — не обработано `sf::Event::Closed`.

## 25. Идеи для рефакторинга

- вынести сам игровой цикл в функцию `run()`;
- завести структуру `WindowConfig` (размер, заголовок, FPS-лимит);
- заменить «голые» числа константами (уже в решении);
- перейти на `sf::Clock` в качестве единственного источника времени.

## 26. Связь с реальной разработкой

«Окно + цикл + ввод + время» — ядро любого 2D-движка. Прямоугольник с
движением — прообраз игрока; `FpsCounter` — прибор для оценки
производительности до профилировщика (см. th50). Правильная обработка входа и
`delta time` с первого дня экономит месяцы переделок.
