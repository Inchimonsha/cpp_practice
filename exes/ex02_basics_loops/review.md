# Разбор: ex02 — Base Defense

## Как решать задумано

Бой — это цикл: `while (running && жив монстр && жив герой)`. Внутри —
действие игрока (`switch`) и ответный ход монстра. Вся «арифметика» жизни —
в `shared/`: `clamp_hp`, `apply_damage`, `is_alive`, `calculate_hit`.

## Ключевые решения

### 1. Логика отделена от интерфейса

`shared/battle.hpp` не знает про консоль. Это позволяет:
- тестировать без ввода с клавиатуры;
- переиспользовать функции в графической версии (prj01).

### 2. Здоровье всегда в `[0, 100]`

Все изменения HP проходят через `clamp_hp`. Именно поэтому «мощный удар
по HP 10» не даёт «-15».

### 3. «Выход» мягко завершает цикл

`running = false`; в этот ход монстр не атакует (`continue`). После цикла
итог проверяется в порядке «мёртв герой → мёртв монстр → выход»: только так
добровольный выход (оба живы) не превращается в «Победу».

## Как выглядит эталонная схема

```
while (running && alive(monster) && alive(hero)):
    print status + menu
    choice = read()
    switch (choice):
        1 → monster = apply_damage(monster, kHeroDamage)
        2 → monster = apply_damage(monster, calculate_hit(kHeroDamage, true))
        3 → hero = clamp_hp(hero + kHealAmount)
        4 → running = false
        default → "Неизвестная команда."
    if not running: continue
    if alive(monster): hero = apply_damage(hero, kMonsterDamage)
print outcome: hero dead → Поражение / monster dead → Победа / иначе Выход
```

## Распределение ответственности

| Слой | Ответственность | Где |
|---|---|---|
| `shared/` | чистая логика: HP, урон, крит | battle.hpp/.cpp |
| `main.cpp` | ввод, меню, цикл, вывод | solution/main.cpp |
| `tests/` | проверка контрактов функций | test_battle.cpp |

## Оценка решения (критерии)

- [ ] Все функции из контракта реализованы и совпадают по сигнатурам.
- [ ] Тесты покрывают: верх/низ `clamp`, урон, лечение-с-капом, крит.
- [ ] HP нигде не превышает `kMaxHp` и не меньше нуля.
- [ ] `-Wall -Wextra` чисто; нет ручного `new/delete`.
- [ ] Читаемость: осмысленные имена, нет «магии», короткие функции.

## Частые недочёты

- лечить напрямую `hero_hp += kHealAmount` → возможен HP > 100;
- проверять «смерть монстра» через `<= 0` там, где есть `is_alive`;
- menu/status печатаются внутри функций `shared/` — ломает тесты;
- урон монстра применяется даже в ход выхода игрока.

## Что оцениваем как «отлично»

- симметричные функции: `apply_damage` возвращает новое HP всегда,
  состояние не «дёргается» снаружи;
- в `switch` нет путаницы между `monster_hp` и `hero_hp`;
- решение прошло `ctest -R ex02` зелёным.
