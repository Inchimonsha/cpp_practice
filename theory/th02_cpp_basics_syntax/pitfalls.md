# Pitfalls: th02 — типы, операторы, условия, циклы

Формат: симптом → причина → решение.

## Типичные ошибки

### 1. «Здоровье уходит в огромное число» при лечении полного HP
- **Проявляется**: `hp = hp + 50;` даёт отрицательное или мусорное значение.
- **Причина**: переполнение `int` — **неопределённое поведение** (UB), или
  `hp` объявлен `unsigned` и `hp - 50` при `hp < 50` даёт ~4.29e9.
- **Решение**: инвариант «HP ∈ [0, max]» держать функциями
  `clamp`-стиля; не объявлять `unsigned` там, где возможны вычитания.

### 2. «Время в игре поехало» — деление целых
- **Проявляется**: `speed = distance / time;` всегда 0 или 1.
- **Причина**: `int / int` → `int`.
- **Решение**: `static_cast<double>(distance) / time;` или `distance * 1.0 / time`.

### 3. «Тайл мигает в начале строки» — вычитание из `unsigned`
- **Проявляется**: при переходе от первого тайла к предыдущему индекс
  становится огромным.
- **Причина**: `index - 1` при `index == 0` и беззнаковом типе даёт
  `4294967295`, выход за границы массива.
- **Решение**: индексы тайлов — `int` с явной проверкой `index > 0`, либо
  `size_t` с проверкой верхней границы до вычитания.

### 4. «-Wall не ругается, а программа ведёт себя странно» — сравнение знаковых/беззнаковых
- **Проявляется**: `i < v.size()` «странно» пропускает ветку.
- **Причина**: `v.size()` — `size_t`; `i` приведён к `size_t`, `-1` стал
  4.29e9.
- **Решение**: счётчики — `std::size_t` или `int` с
  `static_cast<std::size_t>(i)`; не смешивать внутри одного выражения.

### 5. «Сравнение float не срабатывает» — точность
- **Проявляется**: `0.1f * 10.0f == 1.0f` почти всегда ложно.
- **Причина**: `float` хранит приближение; результат зависит от порядка
  операций.
- **Решение**: сравнивать с эпсилон: `std::abs(a - b) <= 1e-5f`.

### 6. «Switch проваливается» — забытый break
- **Проявляется**: выполняется несколько веток подряд.
- **Причина**: отсутствие `break`.
- **Решение**: всегда `break` (или явный комментарий про намеренное
  проваливание, включите `-Wimplicit-fallthrough`).

### 7. «В Release скорость поменялась» — UB от неинициализированной переменной
- **Проявляется**: Debug работает, Release нет.
- **Причина**: `int x;` без инициализации + обращение до присваивания (UB);
  оптимизатор переупорядочивает.
- **Решение**: всегда инициализировать (`int x{0};`).

## Подводные камни

- **`char` и знак**: `char` может быть знаковым или нет в разных реализациях;
  для гарантии — `signed char`/`unsigned char`.
- **`int` могут дать 2 байта** на редких платформах; не полагайтесь на
  фиксированные размеры — используйте `<cstdint>` (`int32_t`) при жёстких
  требованиях.
- **`static` внутри функции** инициализируется один раз и сохраняется между
  вызовами — удобно, но делает функции недетерминированными; не злоупотреблять.
- **Разделители путей** в Windows — `\`, в коде лучше использовать
  `std::filesystem` (тема th33); в этой теме путей в приложениях не бывает.

## Анти-паттерны

- **Переиспользование переменной** под разные смыслы — читаемость и баги.
- **Магические числа** в условиях/циклах — только `constexpr`.
- **`using namespace std;`** в глобальной области — конфликты имён.
