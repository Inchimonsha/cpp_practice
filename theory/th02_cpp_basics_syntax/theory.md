## 4. Почему тема важна в GameDev

- **Координаты, скорость, здоровье, очки** — всё это числа определённых
  типов. Ошибка типа (например, `unsigned` вместо `float`) даёт баг, который
  виден только «на длинной дистанции» (переполнение HP при лечении).
- **Переполнение** `int` — неопределённое поведение (UB): «отрицательное
  здоровье», «внезапный конец мира» в песочницах.
- **Циклы и условия** — это игровой цикл, обработка ввода, генерация мира,
  проверка коллизий. Без них нет игры.

## 5. Теоретическое объяснение

### 5.1. Переменные и базовые типы

Объявление делает две вещи: выделяет область памяти и задаёт **тип** —
множество допустимых значений и операций.

| Тип | Размер (на платформах курса) | Диапазон | Когда использовать |
|---|---|---|---|
| `bool` | 1 байт | `true`/`false` | флаги, «жив ли» |
| `int` | 4 байта | ≈ ±2.1e9 | счёты, индексы, размеры |
| `unsigned int` | 4 байта | 0 … ≈4.3e9 | **только** там, где отрицательные невозможны |
| `float` | 4 байта | ~6–7 значащих цифр | координаты, скорости в играх |
| `double` | 8 байт | ~15–16 значащих цифр | точные расчёты, мир-координаты |
| `char` | 1 байт | при реализации знаковый или нет | символы, байты |
| `std::string` | динамический | — | текст (тема th06) |

Точные размеры не гарантируются стандартом; в курсе приняты размеры для
64-битных Windows/Linux (GCC). Проверяйте при необходимости
`sizeof`/`<limits>`, а не предполагайте.

Рекомендация для игр: **координаты и скорости — `float`**, счёты предметов и
здоровья — целые (`int`), размеры контейнеров — `std::size_t` (беззнаковый).
`double` оправдан для «мировых» координат в песочницах с огромной картой.

### 5.2. Инициализация

Предпочитайте инициализацию, а не объявление «с последующим присваиванием»:

```cpp
int score = 0;                 // классика
int score2{0};                 // brace-инициализация (C++11): не допускает сужения
double speed = 3.0;            // double-литерал
float speed2 = 3.0f;           // f-суффикс — float
bool alive = true;
```

`int narrow{3.7};` — **ошибка компиляции** (сужение double→int), тогда как
`int narrow = 3.7;` тихо получит `3`. Привычка к `{}` ловит целый класс багов.

### 5.3. Константы

| Ключевое слово | Что значит | Примеры использования |
|---|---|---|
| `const` | не менять **после инициализации** (может вычисляться в рантайме) | параметры-настройки, значения из конфигурации |
| `constexpr` | вычислимо при компиляции | константы уровня `kMoveSpeed`, размеры окон |
| `static` (в функции) | одна копия на всю программу, живёт весь цикл | счётчик вызовов, состояние без глобальных переменных |

```cpp
constexpr long kWindowWidth = 800;   // известно при компиляции
const long kScoreLimit = read_from_config();  // рантайм, но не меняется
```

Курс требует: константы-настройки — `constexpr`; «вычисленные один раз» —
`const`. Менять такие значения через константы — признак плохой архитектуры.

### 5.4. Операторы

Приоритет и ассоциативность — в `cheatsheet.md`. Главное:
- арифметика: `+ - * / %`;
- сравнение: `== != < <= > >=`;
- логика: `&& || !` (короткое замыкание);
- инкремент/декремент: `i++ ++i`;
- составные присваивания: `+= -= *= /= %=`;
- побитовые (для флагов-битмасок): `& | ^ ~ << >>`.

**Деление целых** отбрасывает дробную часть: `7 / 2 == 3`, `-7 / 2 == -3`
(в C++20 округление к нулю). Для «честного» деления нужен `double`:
`7.0 / 2.0 == 3.5`.

**Остаток**: `7 % 2 == 1`; полезен для «чётный/нечётный», цикличных индексов.

Короткое замыкание: `a && b` не вычислит `b`, если `a` ложно — удобно для
проверок вида `i < n && items[i] > 0`.

### 5.5. Условия

```cpp
if (hp <= 0) {
    die();
} else if (hp < 25) {
    warn_low_hp();
} else {
    keep_fighting();
}
```

- `if` с многими ветками на одном значении — кандидат на `switch`.
- `switch` используйте для целых и `enum`; после каждой ветки — `break`,
  иначе код «провалится» дальше (иногда специально, но тогда — комментарий).
- Тернарный оператор: `int tag = is_bonus ? 10 : 1;` — для коротких выражений.
- C++17 **if-init**: `if (auto* obj = find(); obj) { ... }` — переменная живёт
  только внутри ветки; образец частого паттерна «проверка ввода». (SFML 3 это
  использует везде.)

### 5.6. Циклы

```cpp
for (int i = 0; i < 10; ++i)      { /* известное число итераций */ }
while (hp > 0)                    { /* условие в начале */ }
do { roll_dice(); } while (again); // хотя бы один раз
for (auto& m : monsters)          { /* range-for: по элементам */ }
```

- `break` — выйти из цикла, `continue` — перейти к следующей итерации.
- `for (int i = 0; i < n; ++i)` — счётчик **`int`, а не `unsigned`**, если
  граница берётся из внешнего мира (иначе `n - i` при `n < i` уйдёт в минус).
- Циклы с «волшебными» числами — повод для `constexpr`.

### 5.7. Преобразования типов

- **Неявные** (только осознанно): `int` → `long`, `int` → `double` —
  расширение, безопасно; `double` → `int`, `long` → `int` — **сужение**,
  теряет данные.
- **Явные**: `static_cast<int>(x)` — контролируемое преобразование. Запрет
  C-стиля `(int)x` в курсе.
- `unsigned`-арифметика модулярна: `0u - 1 == 4294967295u`. Отсюда — баг
  «ячейка мигает при первый клетке», когда индекс `-1` превращается в большое
  число. Правило: **не смешивайте `signed` и `unsigned`**, а вычитание
  беззнаковых — только при доказанной коррекности.

## 9. Применение в 2D-играх

- Позиция игрока: `float x = 0.0f; x += kSpeed * dt;`.
- Здоровье: `int hp; if (hp > kMaxHp) hp = kMaxHp;`.
- Индексы тайлов: `int col = x / kTileSize;` с проверкой границ.
- Игровой цикл — `while (window.isOpen())` (SFML, тема th23).

## 10. Применение в песочницах

- Координаты чанков: два `int` (или `long`) вместо `float` — координаты
  мира могут расти без ограничений; сравнение чанков — целочисленное.
- Счётчики блоков и ресурсов: целые; переполнение в таких счётчиках —
  классический баг «мира после 2^31 блоков».

## 11. Взаимодействие с SFML

- `sf::Vector2f` — вектор из двух `float` (SFML 3); координаты, размеры,
  скорости в коде курса — `float`.
- События и `sf::VideoMode` принимают размеры (`unsigned`);
  `sf::VideoMode({kWindowWidth, kWindowHeight})` — фигурные скобки
  (инициализация, см. 5.1).
- API SFML широко применяет паттерн «if-init + optional» из 5.5 —
  приятная встреча после этой темы.

## 12. Типичные ошибки

Кратко (подробно — [pitfalls.md](pitfalls.md)):

- переполнение `int` (UB) и модулярная арифметика `unsigned`;
- деление целых вместо вещественного;
- сравнение `float` на равенство;
- смешивание `signed`/`unsigned` в сравнениях;
- сужение типа неявным преобразованием.

## 13. Подводные камни

- `char` бывает знаковым и нет — `char c = 200;` не переносимо;
- размеры типов зависят от платформы — не зашивать их в код;
- `switch` не использует `break` → «проваливание»;
- короткое замыкание — не вычисляйте «побочный» код в условиях.

## 14. Советы по проектированию

- **const-first**: всё, что не меняется, — `constexpr`/`const`. Проще читать,
  безопаснее изменять.
- Не используйте `unsigned` «для красоты»: смешивание со `signed` создаёт
  ошибки. Счётчики циклов — `int`.
- Одна функция — одна задача; условия и циклы внутри должны читаться как
  предложение.
- Используйте `switch` для enum-состояний (игровой статус, тип тайла) —
  компилятор предупредит о пропущенных значениях (`-Wswitch`).
