# th04 — Ссылки и указатели, управление памятью

## 1. Название

Ссылки и указатели — механизмы адресации в C++ — и модель памяти (стек, куча).
Модуль 1.

## 2. Цели обучения

После этой темы вы:

- передаёте и возвращаете объекты по ссылке, понимаете время жизни;
- используете указатели осознанно: `nullptr`, разыменование, указатель как
  «может не иметь значения»;
- различаете стек и кучу: кто создаёт, кто освобождает, чем грозит забыть;
- объясняете, почему в курсе запрещён ручной `new`/`delete` (RAII — th09);
- читаете ошибки сегментации и `std::bad_alloc`.

## 3. Предварительные знания

## 4. Почему тема важна в GameDev

- Игровые объекты и текстуры — большие; копия в каждом кадре «убивает» FPS.
  Ссылки и `const&` — бесплатная передача.
- Камера, трансформации, коллизии оперируют «одним и тем же» объектом;
  ошибки времени жизни здесь — краши «игра вылетает раз в 10 минут».
- Понимание стека/кучи — фундамент для th09 (умные указатели) и th52
  (производительность: аллокации).

## 5. Теоретическое объяснение

### 5.1. Ссылки

Ссылка — псевдоним объекта; **обязана** быть инициализирована и не может быть
перепривязана:

```cpp
int score = 100;
int& ref = score;      // ref — другое имя score
ref = 50;              // теперь score == 50
```

- Нельзя оставить «ссылку на ничто»: `int& bad;` — ошибка компиляции.
- Передача в функцию по `T&` — мутация оригинала (см. th03); по `const T&` —
  чтение без копии.
- Возврат `T&` из функции — «наружу», но время жизни должно превышать вызов.

### 5.2. Указатели

Указатель хранит адрес; его можно переприсвоить, сравнить с `nullptr`,
разыменовать через `*p`, взять адрес `&x`:

```cpp
int a = 10;
int b = 20;
int* p = &a;   // p указывает на a
p = &b;        // перепривязка — можно
*p = 30;       // b == 30
p = nullptr;   // «нет значения»
if (p) { /* безопасно разыменовать */ }
else   { /* успокойся */ }
```

Правила безопасности:
- **проверяйте `nullptr`** перед разыменованием, если указатель пришёл извне;
- перед разыменованием думайте о времени жизни объекта;
- разыменование нулевого/висячего указателя — UB (краш `0xC0000005`).

### 5.3. Когда ссылка, когда указатель

| Критерий | Ссылка | Указатель |
|---|---|---|
| «Всегда есть значение» | да | может быть `nullptr` |
| Перепривязка | нет | да |
| Арифметика (массив) | нет | да (назад, осторожно) |
| Хранение «на будущее» (в контейнере/поле) | нельзя (в C++20 — нельзя) | да |

Правило курса: по умолчанию — `const T&`; `T&` — когда нужна мутация из
аргумента; указатель — когда «значения может не быть» или нужно хранить
адрес дольше вызова (тогда — умные указатели, th09).

### 5.4. Стек и куча

| | Стек | Куча (динамическая память) |
|---|---|---|
| Владелец | автоматически, на выходе из блока | вы, через `new`/`delete` или умные указатели |
| Скорость | быстрый | медленнее (аллокация) |
| Размер | ограничен (~МБ) | большой, до исчерпания |
| Типичные объекты | локальные, параметры | контейнеры, ресурсы больших размеров |

```cpp
{
    int on_stack = 1;                  // стек; освободится сам
    auto* on_heap = new int(2);        // куча; удалять ВАМ
    delete on_heap;                    // кто забыл — утечка
}
```

Забытый `delete` → утечка памяти; двойной `delete` и `delete` после выхода
из области → UB. Именно поэтому в курсе **запрещён ручной `new`/`delete`**:
управление временем жизни автоматизировано (`std::unique_ptr` — th09),
что резко сокращает класс критических багов.

### 5.5. Массивы и указатели

Имя массива «вырождается» в указатель на первый элемент, но это **не одно и
то же**: `sizeof(arr)` верен только для массива. На практике работа с
последовательностями идёт через `std::array`/`std::vector` (th05), а
`std::span` (th05) даёт безопасное «окно» над данными.

## 6. Синтаксис

```cpp
int x = 5;
int& rx = x;              // ссылка
const int& crx = x;       // const-ссылка (чтение)
int* px = &x;             // указатель
bool has = px != nullptr;
if (px) { *px = 6; }      // разыменование под защитой
```

## 8. Практические примеры на Lua

В Lua **нет указателей**: таблицы передаются по ссылке всегда, числа и строки
копируются. Это одна из причин, почему Lua-код проще в маленьких скриптах и
опасен в больших (см. th15, th18).

## 10. Применение в песочницах

- Тысячи тайлов/сущностей: не копировать, а ссылаться; изменение чанка —
  по ссылке.
- Указатели-владельцы («какой блок содержит сущность») — только умные
  указатели (th09), без ручного освобождения.

## 11. Взаимодействие с SFML

- Методы SFML принимают векторные параметры по значению и возвращают по
  значению (`sprite.move({dx, dy})`, `getPosition()`); для состояний игровых
  объектов вы используете свои типы с `const&`.
- SFML 3 `pollEvent()` — `std::optional` (th10): «значения может не быть» —
  как `nullptr`, но безопаснее.

## 12. Типичные ошибки

- разыменование `nullptr` / висячего указателя;
- возврат ссылки на локальную переменную;
- утечка из-за забытого `delete`;
- путаница `&` в объявлении («ссылка») и `&` в выражении («адрес»);
- передача «большого объекта по значению» из невнимательности.

## 13. Подводные камни

- `const int*` (указатель на константу) ≠ `int* const` (константный указатель);
- ссылка на элемент контейнера «умирает» при перераспределении (`vector`);
- стек в debug-сборках имеет guard-страницы: глубоко вложенный рекурсивный
  вызов → переполнение стека.
- `delete` для памяти, выделенной `new[]`, — UB (не смешивайте).

## 14. Советы по проектированию

- «Ссылка по умолчанию, указатель по необходимости» — код читается проще.
- Не создавайте указатели «на будущее» там, где достаточно прохождения
  по значению или `const&`.
- Владельцы объектов — **только** RAII-типы (th09). Указатели не-владельцы
  задокументируйте (`/* не владеет */`).
