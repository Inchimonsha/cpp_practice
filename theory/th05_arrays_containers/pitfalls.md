# Pitfalls: th05 — массивы и контейнеры

Формат: симптом → причина → решение.

## Типичные ошибки

### 1. «Выход за границы без ошибки… потом краш»
- **Проявляется**: `v[i]` читает мусор или падает редко.
- **Причина**: `operator[]` не проверяет границы; за границей — UB.
- **Решение**: `v.at(i)` где возможен выход; или проверяйте `i < v.size()`.

### 2. «Ссылка/итератор сломались после push_back»
- **Проявляется**: код, работавший при маленьком размере, падает при большом.
- **Причина**: `push_back` при `size == capacity` перераспределяет буфер.
- **Решение**: не держите ссылок/итераторов через мутации; либо
  `v.reserve(нужно_заранее)`.

### 3. «v.size() - 1 == 4294967295»
- **Проявляется**: цикл по массиву ведёт себя странно, выходы огромные.
- **Причина**: `size()` — `std::size_t` (unsigned), `- 1` переполняет.
- **Решение**: сравнение с `0` до вычитания; или индексы как `int` с проверками.

### 4. «Range-for не меняет элементы»
- **Проявляется**: `for (auto x : v) x = 0;` не влияет на `v`.
- **Причина**: итерация по **копиям** (`auto x`).
- **Решение**: `for (auto& x : v)`.

### 5. «Модификация контейнера в цикле ведёт себя непредсказуемо»
- **Проявляется**: пропуски элементов, дубликаты или краши.
- **Причина**: `for (auto& x : v) { v.erase(...); }` инвалидирует итератор.
- **Решение**: собирать индексы/условия, удалять после цикла; или идти с конца
  по индексам. (Более элегантно — `std::erase_if`, th12.)

### 6. «Медленно вставляет в начало»
- **Проявляется**: FPS проседает при частых `v.insert(v.begin(), ...)`.
- **Причина**: сдвиг всех элементов — `O(n)`.
- **Решение**: `std::deque`/`std::vector` с реверсом, или менять структуру.

## Подводные камни

- `reserve` резервирует **ёмкость**, а не размер; `v.size()` не изменится.
- `std::array` — это тип, размер фиксирован при компиляции.
- Индексы по умолчанию — `std::size_t`; параметрами функций делайте
  `std::size_t` и проверяйте границы.
- В циклах «до `(int)v.size()`» явное приведение лучше неявного сравнения.

## Анти-паттерны

- C-массивы и «голые» пары `(ptr, len)` там, где есть `std::span`.
- Несколько параллельных `vector`, индексы которых «должны совпадать».
- Мелкие `vector` в каждом кадре без `reserve` (аллокации — th53).
