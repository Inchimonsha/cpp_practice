# th05 — Массивы и контейнеры

## 1. Название

Последовательные контейнеры C++: C-массивы, `std::array`, `std::vector`,
итераторы и `std::span`. Модуль 1.

## 2. Цели обучения

После этой темы вы:

- выбираете между `std::array` и `std::vector` по требованиям к размеру;
- добавляете, удаляете и обходите элементы, понимаете `size`/`capacity`,
  `reserve`;
- используете range-for и итераторы, знаете границы `[]`/`at()`;
- передаёте «окно» данных через `std::span` без копирования.

## 3. Предварительные знания

- th02–th04: типы, функции, ссылки, стек/куча.

## 4. Почему тема важна в GameDev

- Пакеты монстров, тайлы уровня, пули, спрайты — всё это последовательности.
- `std::vector` без `reserve` — лишние перераспределения; на сотнях тысяч
  объектов это просадки FPS (подробно — th53).
- Итераторы + алгоритмы (th12) — стандартный способ писать «одно и то же
  один раз».

## 5. Теоретическое объяснение

### 5.1. C-массивы — почти не используем

```cpp
int arr[5] = {1, 2, 3, 4, 5};   // фиксированный размер; arr.size() нет
```

Опасности: нет границ, «вырождение» в указатель (th04), `sizeof`-ловушки.
В курсе C-массивы фигурируют только в историческом контексте.

### 5.2. std::array — фиксированный размер

```cpp
#include <array>
std::array<int, 5> a{1, 2, 3, 4, 5};
std::size_t n = a.size();       // знает свой размер
a.at(9);                        // бросит std::out_of_range
auto [x, y, z] = coordinate;    // structured bindings (C++17)
```

- Размер известен при компиляции; память — на стеке; никаких аллокаций.
- Подходит для константных таблиц: направления, сочетания клавиш, цены.

### 5.3. std::vector — растущий контейнер

```cpp
std::vector<int> v;            // пустой
v.push_back(1);                // добавить копию
v.emplace_back(2);             // добавить, конструируя на месте (быстрее)
v.reserve(1000);               // зарезервировать ёмкость заранее
v.size();                      // количество элементов
v.capacity();                  // ёмкость буфера (>= size)
v[0];                          // быстрый доступ без проверки
v.at(0);                       // доступ с проверкой (бросит исключение)
```

- Элементы лежат **непрерывным блоком в куче**; при росте свыше `capacity`
  буфер перераспределяется, а ссылки/итераторы на элементы **инвалидируются**.
- `emplace_back` против `push_back`: для нетривиальных типов `emplace_back`
  избегает временной копии.
- Удаление из середины сдвигает элементы (`O(n)`) — для частых удалений из
  середины нужны другие структуры (th12/th32).

### 5.4. Итераторы

```cpp
for (auto it = v.begin(); it != v.end(); ++it) { *it; }
for (const auto& x : v) { /* чтение */ }
for (auto& x : v) { x += 1; }                 // изменяем элементы
```

- Range-for по контейнеру — это синтаксический сахар над итераторами.
- `begin()/end()` — «полуоткрытый» диапазон `[begin, end)`.
- Итераторы инвалидируются при модификациях, изменяющих размер/буфер
  (`push_back`, `erase`, `resize`).

### 5.5. std::span — безопасное «окно» (C++20)

```cpp
void process(std::span<const int> values) {
    for (int v : values) { /* ... */ }
}
```

- Не владеет данными; хранит указатель и размер.
- Принимает и `std::array`, и `std::vector`, и C-массив — единый интерфейс.
- Идеален для передачи «чтения» без копирования и без пары `(ptr, size)`.

## 6. Синтаксис

```cpp
#include <array>
#include <span>
#include <vector>

std::array<int, 4> dirs{1, -1, 1, -1};
std::vector<float> speeds{10.0f, 20.0f};

float total(std::span<const float> data);   // общий интерфейс
```

## 8. Практические примеры на Lua

В Lua работает один универсальный контейнер — таблица (th15). В C++ выбор
контейнера явно выражает требования к памяти и времени — это навык, который
пригодится при встраивании Lua (th18).

## 9. Применение в 2D-играх

```cpp
std::vector<Bullet> bullets;         // растущий арсенал
bullets.erase(bullets.begin() + i);  // вылетевшая пуля
for (auto& b : bullets) { b.update(dt); }
```

## 10. Применение в песочницах

- Чанк тайлов фиксированного размера — `std::array` или плоский
  `std::vector<std::uint16_t>` размером `W*H`.
- Динамические сущности — `std::vector`, удаление — swap-pop или compacting
  (th53).

## 11. Взаимодействие с SFML

- SFML редко отдаёт диапазоны напрямую; события прогоняйте циклом
  `while (const std::optional ev = window.pollEvent())` — это итерационный
  паттерн.
- Списки анимаций/эффектов/слоёв в своих проектах — `std::vector`.

## 12. Типичные ошибки

- `v[i]` за границей (UB) вместо `v.at(i)`;
- модификация контейнера во время range-for по нему;
- использование удалённого элемента после `erase`;
- забытый `reserve` → лишние перераспределения;
- хранение ссылки на элемент, полученной до `push_back`.

## 13. Подводные камни

- Инвалидация итераторов и ссылок при росте вектора;
- `size()` — `std::size_t` (беззнаковый): `v.size() - 1` при пустом векторе —
  огромное число;
- range-for не меняет элементы без `&`;
- `std::array` нельзя «пересоздать» другим размером — это другой тип.

## 14. Советы по проектированию

- `std::vector` — контейнер по умолчанию; `std::array` — для констант и
  фиксированных таблиц; другие контейнеры — по обоснованной причине.
- Принимайте «набор данных» параметром `std::span<const T>`.
- Держите инварианты «размеры согласованы» у наборов (например, параллельных
  векторов лучше заменить вектором структур).
