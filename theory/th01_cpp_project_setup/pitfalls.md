# Pitfalls: Настройка проекта

Развёрнутый список типичных ошибок и подводных камней темы `th01`.
Формат: симптом → причина → решение.

## Типичные ошибки

### 1. Ошибка линкера «undefined reference to ...»
- **Проявляется**: на стадии линковки, после компиляции.
- **Причина**: функция объявлена (`#include <...>`), но определение не попало
  в линковку: не добавлен `.cpp` в цель, не прилинкована библиотека
  (например, `-lsfml-graphics`), или неверный порядок `-l` при ручной линковке.
- **Решение**: добавить файл/библиотеку в CMake-цель; при ручной линковке
  библиотеки располагать после объектных файлов.

### 2. Запуск «из IDE работает, из терминала нет»
- **Проявляется**: игра не находит шрифт/уровень при запуске из терминала.
- **Причина**: рабочая директория разная; путь к ресурсу относителен рабочей
  директории, а не файла программы.
- **Решение**: строить пути относительно каталога исполняемого файла и
  логировать их.

### 3. Симптом «в Release — крашится, в Debug — нет»
- **Проявляется**: только на оптимизированной сборке.
- **Причина**: неопределённое поведение (UB) — неинициализированные переменные,
  выход за границы массива, `signed overflow`, чтение после `free`. `-O2`
  переупорядочивает операции и обнажает зависимость от UB.
- **Решение**: искать UB в коде (санитайзеры — тема `th50`).

### 4. `assert` «пропадает» в Release
- **Проявляется**: проверка, работавшая в Debug, не срабатывает в Release.
- **Причина**: в Release определён `NDEBUG`, и `assert` не компилируется.
- **Решение**: не писать значимую логику в `assert`; для реальных проверок —
  явные ветки с `throw` или логированием.

### 5. Коммит артефактов в репозиторий
- **Проявляется**: репозиторий раздувается `build/` и `third_party/`.
- **Причина**: `git add .` без `.gitignore`.
- **Решение**: добавить стандартный `.gitignore` (в курсе он уже есть) и
  проверять `git status` перед `commit`.

### 6. Путаница с генератором CMake
- **Проявляется**: разные каталоги сборки для разных IDE/генераторов
  конфликтуют.
- **Причина**: конфигурации с разными генераторами в одном каталоге `build/`.
- **Решение**: использовать отдельные каталоги (`build/`, `build-msvc/`) и не
  смешивать.

### 7. SFML-приложение «собирается, но падает при запуске» (`0xC0000005`)
- **Проявляется**: exe корректно собирается и линкуется (DLL пребилта найдены),
  но при создании окна падает; в отладчике — `HEAP[...]: Invalid address
  specified to RtlFreeHeap`.
- **Причина**: пребилт SFML собран под UCRT-тулчейн (winlibs GCC 14.2), а
  приложение собрано msvcrt-тулчейном (например, GCC 13.2 с
  `-static-libgcc`/`-static-libstdc++`). `std::string`/`std::vector`, созданные
  в exe, освобождаются в DLL из другого CRT — кросс-heap-коррупция.
- **Решение**: использовать UCRT-базированный MinGW (MSYS2 `ucrt64` или
  winlibs UCRT, GCC ≥ 14). Рантайм-DLL (`libstdc++-6.dll`,
  `libgcc_s_seh-1.dll`, `libwinpthread-1.dll`) должны быть той же версии, что
  и компилятор; в курсе `cmake/sfml.cmake` копирует их на POST_BUILD.
  Диагностика: `objdump -p app.exe | findstr DLL` — сравнить CRT, которые
  тянет exe и DLL пребилта.

## Подводные камни

### 1. Регистр и разделители путей
Windows в большинстве конфигураций регистронезависим, Linux — регистрозависим.
Переносимый код не должен полагаться на регистр в именах и на константу
`/` или `\`: используйте `std::filesystem` (см. `th33_game_data`) и пути CMake
с `/`.

### 2. «Магические» пути в коде: `"assets/font.ttf"`
Рабочая директория ненадёжна. Переносимая схема — ресурсы рядом с
исполняемым файлом либо абсолютные пути из конфигурации. В курсе принят
способ «рядом с исполняемым файлом» (см. ex01).

### 3. Порядок `-l` в ручной линковке MinGW
`g++ main.cpp -lsfml-graphics` — ок; `g++ -lsfml-graphics main.cpp` — может
упасть на линковке из-за порядка обработки архивов. С CMake этой проблемы нет.

### 4. Символ `\n` и кодировка консоли
Русские строки в консоли Windows могут отображаться кракозябрами из-за кодовой
страницы. Проверяйте вывод простых ASCII-сообщений и устанавливайте кодировку
консоли (`chcp 65001`) при необходимости; в CI избегайте национальных символов
в ключевых строках вывода.

### 5. Антивирус и время сборки
На Windows средства защиты могут замедлять сборку или блокировать DLL-копии.
Не «чините» это отключением защиты вслепую; сначала проверьте, что дело именно
в ней (например, добавьте каталог сборки в исключения).

## Анти-паттерны

- **Отключать все предупреждения** ради «чистого» каталога сборки.
- **Копировать файлы руками в `build/`** — место артефактов не в репозитории.
- **Дёргать `git add .` без просмотра** — легко закоммитить ключи или ассеты с
  запрещённой лицензией.
- **Собирать только в IDE** — без понимения команд сборки невозможен CI.
