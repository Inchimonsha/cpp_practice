# th03 — Функции и области видимости

## 1. Название

Функции — атомарные действия программы; области видимости — правила доступа к
именам. Модуль 1.

## 2. Цели обучения

После этой темы вы:

- объявляете и определяете функции, выбираете тип параметров
  (значение / ссылка / `const`-ссылка) и возврата;
- объясняете перегрузку, аргументы по умолчанию, `inline`;
- различаете области видимости (блочная, функция, namespace) и понимаете,
  что такое `static` в функции;
- раскладываете код на `.hpp` (объявления) и `.cpp` (определения) по правилам
  курса.

## 3. Предварительные знания

- th01: сборка многофайловых проектов через CMake;
- th02: типы, константы, условия, циклы.

## 4. Почему тема важна в GameDev

- Игровой цикл, коллизии, подсчёт очков — всё это функции. Плохо названные и
  длинные функции делают игру неподдерживаемой уже на `prj01`.
- Правильная передача параметров определяет производительность: копирование
  большого `std::vector` в каждом кадре убивает FPS; `const&` — бесплатно.
- Области видимости защищают от «внезапного изменения x другим кодом».

## 5. Теоретическое объяснение

### 5.1. Объявление и определение

```cpp
int damage(int base, int mult);   // объявление (в .hpp): «функция существует»
int damage(int base, int mult) {  // определение (в .cpp): тело
    return base * mult;
}
```

Определение можно вызывать после объявления. Без объявления вызов выше места
определения — ошибка компиляции.

### 5.2. Способы передачи параметров

| Способ | Копия? | Изменение оригинала? | Когда |
|---|---|---|---|
| `void f(int x)` | да | нет | маленькие значения, не хотим менять |
| `void f(int& x)` | нет | да | нужно изменить у вызывающего |
| `void f(const int& x)` | нет | нет | большие объекты, читаем |
| `void f(int* p)` | указатель | да (через `*p`) | «могу не иметь значения» (nullable) |

Правило курса: **по умолчанию — `const&`; значение — для мелких типов; ссылка
`&` — только когда нужно вернуть результат через параметр**.

### 5.3. Возврат результатов

- Возвращайте значение по смыслу: `int hit() { return 10; }`.
- «Несколько результатов» — верните структуру или `std::optional` (th10), а
  не несколько `out`-параметров (кроме случаев, когда это уместно по
  производительности).
- Возврат ссылки/указателя на **локальную** переменную — висячий
  (dangling) объект: UB. Об этом подробнее в th04.

### 5.4. Перегрузка и аргументы по умолчанию

```cpp
int scale(int value) { return value * 2; }
int scale(int value, int factor) { return value * factor; }
double scale(double value) { return value * 1.5; }
```

- Перегрузка — разные сигнатуры (типы/число параметров) с одним именем.
- Аргументы по умолчанию: `void apply_gravity(float g = 9.81f);` — указываются
  справа, в объявлении (не в определении) — иначе конфликт.
- Не перегружайте «по возвращаемому значению» — так нельзя.

### 5.5. `inline`

- `inline` разрешает одно определение в нескольких единицах трансляции —
  стандартный способ держать маленькие функции в заголовках
  (см. `test.hpp` курса). Для больших функций в `.cpp` не нужен.

### 5.6. Области видимости (scope)

| Область | Виден | Живёт |
|---|---|---|
| блочная (`{ }`) | внутри блока | до конца блока |
| параметр функции | в теле функции | во время вызова |
| namespace (в т.ч. анонимный) | внутри namespace | вся программа |
| глобальная | везде (избегать!) | вся программа |
| `static` в функции | внутри функции | вся программа (одна копия) |

- **Анонимный namespace** (`namespace { ... }`) — «внутреннее связывание»:
  имена видны только в текущем `.cpp`. Это основной инструмент для приватных
  деталей реализации без глобальных переменных.
- **Нет глобальных изменяемых переменных** без объяснения (правило курса).

### 5.7. Разделение `.hpp`/`.cpp`

- `.hpp`: объявления классов/функций, константы, `#pragma once`.
- `.cpp`: определения (*одно* определение на программу).
- CMake перечисляет `.cpp` в цели; заголовки — в `target_include_directories`.

## 6. Синтаксис

```cpp
// point.hpp
#pragma once
int manhattan(int x, int y);

// point.cpp
#include "point.hpp"
int manhattan(int x, int y) { return std::abs(x) + std::abs(y); }

// применение
auto dist = manhattan(3, -4);  // 7
```

## 10. Применение в песочницах

- Функции генерации чанка `Chunk generate(int seed, Vec2i coord);` —
  чистые, детерминированные — основа тестабильности (th42).
- «Сервисные» функции физики/движения — `const&` и без глобального состояния.

## 11. Взаимодействие с SFML

- `sf::VideoMode({w, h})` — это конструктор; SFML использует функции
  с возвратом по значению и `const&`-параметры. Следуйте тому же стилю.
- `window.pollEvent()` возвращает `std::optional` — функции могут «не вернуть
  результат»; это тема th10.

## 12. Типичные ошибки

- изменение параметра-копии вместо оригинала (забыли `&`);
- возврат ссылки/указателя на локальную переменную;
- глобальные переменные-«заглушки» вместо параметров;
- перегрузка, неотличимая по типам (`f(int)` и `f(int)` — нет).

## 13. Подводные камни

- Анонимный `namespace` **внутри** функции — локальная сущность, не путать;
- аргумент по умолчанию пишется в объявлении, а не в определении;
- `-Wshadow` предупредит о тени имен — не отключайте.

## 14. Советы по проектированию

- Маленькие функции с ясными именами; 10–30 строк максимум.
- Параметры-«выключатели» (`bool force`) — запах; сделайте две функции.
- Чистые функции (без `static`-состояния и ввода-вывода) — самый простой
  кандидат для unit-тестов (prj01 так и устроен).
