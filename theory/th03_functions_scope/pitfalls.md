# Pitfalls: th03 — функции и области видимости

Формат: симптом → причина → решение.

## Типичные ошибки

### 1. «Функция ничего не меняет, а должна»
- **Проявляется**: `normalize(velocity);` не меняет `velocity`.
- **Причина**: параметр передан по значению — изменилась копия.
- **Решение**: `void normalize(Vector& v)` — по ссылке (см. th04).

### 2. «Программа падает случайным образом» — висячий указатель
- **Проявляется**: редко, нестабильно, чаще после вызова функции.
- **Причина**: `return &local_variable;` — память локальной переменной
  освобождена.
- **Решение**: возвращать по значению или через `out`-параметр; никогда —
  адрес локальной переменной.

### 3. «Аргумент по умолчанию не работает»
- **Проявляется**: при вызове `f(5)` — ошибка «слишком мало аргументов».
- **Причина**: умолчание написано в определении, а не в объявлении; либо
  вызов до объявления.
- **Решение**: умолчания — только в объявлении `.hpp`.

### 4. «Две функции не могут существовать» — конфликт по возвращаемому типу
- **Проявляется**: перегрузка не создаётся.
- **Причина**: `int f()`, `double f()` — одинаковые сигнатуры (имя + параметры).
- **Решение**: перегрузка различается **типами/числом параметров**;
  имя результата вынесите в имя функции (`f_int`, `f_double`).

### 5. «Функция видит `x`, которого быть не должно» — тень имени
- **Проявляется**: параметр перекрывает глобальную переменную.
- **Причина**: имя параметра совпадает с именем снаружи; локальная область
  «тенит» внешнюю.
- **Решение**: компилировать с `-Wshadow`; не использовать глобальные имена
  без необходимости.

### 6. «Мир меняется сам» — скрытое состояние через static
- **Проявляется**: несколько вызовов одной функции дают разный результат
  при одинаковых аргументах.
- **Причина**: `static`-переменная в функции.
- **Решение**: явно передавать состояние параметром; `static` оставить
  только там, где нужен «счётчик всей программы».

## Подводные камни

- Перегрузка и аргументы по умолчанию вместе: `f(int)` + `f(int, int=0)`
  делают вызов `f(5)` неоднозначным.
- `inline` в `.cpp` бессмыслен — он нужен для заголовков.
- Функции из разных `.cpp` со «скрытым» анонимным namespace не конфликтуют —
  это фича, не баг.
- Определение функции в `.hpp` **без** `inline` → ошибка ODR при подключении
  в два `.cpp`.

## Анти-паттерны

- Мега-функция на 200 строк — разбивайте.
- Цепочка `bool`-параметров (`draw(sprite, flip, glow, shadow, outline)`).
- «Сервисные» функции с вводом/выводом внутри — плохо тестируются;
  возвращайте данные, печатайте снаружи.
