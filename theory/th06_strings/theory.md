# th06 — Строки

## 1. Название

Текстовые данные в C++: `std::string`, `std::string_view`, кодировки.
Модуль 1.

## 2. Цели обучения

После этой темы вы:

- создаёте и изменяете строки, конкатенируете, ищете и вырезаете подстроки;
- преобразуете числа в строки и обратно (`std::to_string`, `std::stoi`);
- применяете `std::string_view` для чтения без копий и понимаете его
  ограничения по времени жизни;
- знаете базовые факты об UTF-8 и о кодовой странице консоли Windows.

## 3. Предварительные знания

- th02–th05: типы, функции, контейнеры.

## 4. Почему тема важна в GameDev

- Имена героев, тексты диалогов, команды консоли, сохранения, пути к
  ассетам — всё строки.
- Заголовки окон, FPS-счётчики, логи — постоянная конкатенация; без
  оптимизации строки дают аллокации в каждом кадре.
- `string_view` — стандартный способ читать текст, не копируя его в каждом
  вызове (парсеры команд, DSL).

## 5. Теоретическое объяснение

### 5.1. std::string — строка-владелец

```cpp
std::string name = "Player";       // из литерала
std::string greeting = "Привет, " + name + "!";  // конкатенация
```

| Операция | Пример | Что делает |
|---|---|---|
| конкатенация | `a + b`, `a += "x"` | новые строки (аллокации!) |
| длина | `s.size()`, `s.length()` | число символов (а не байт всегда) |
| доступ | `s[i]`, `s.at(i)`, `s.front()`, `s.back()` | как у `std::vector` |
| поиск | `s.find("x")` | позиция или `npos` |
| вырезка | `s.substr(pos, len)` | новая строка-копия |
| вставка/удаление | `s.insert`, `s.erase` | как у `std::vector` |
| C-совместимость | `s.c_str()` | `const char*` (с `\0`) |
| prepend/append | `s.append(...)` | одиночные операции |
| числа | `std::to_string(42)`, `std::stoi(s)` | преобразования |

`substr` возвращает **копию** — если нужна только проверка, смотрите
`string_view`.

### 5.2. std::string_view — чтение без копии (C++17)

```cpp
std::string_view sv = "some text";   // указывает на данные литерала
void describe(std::string_view key) { /* ... */ }
```

- Не владеет; `{ptr, size}`; нулевой терминатор не гарантирован.
- Быстро: нет аллокаций. Параметры-«прочитать текст» — `string_view`.
- Опасность: `sv` указывает на чужие данные; если они удалены — висячий
  `view` (как указатель).
- Не храните `string_view`, возвращённый из `substr()` временной строки,
  дольше строки.

### 5.3. Кодировки: UTF-8 и консоль Windows

- Современная реальность — **UTF-8**: кодировка по умолчанию в файлах и
  большинстве API. Один «символ» может занимать 1–4 байта, поэтому
  `s.size()` — это байты, а не «буквы».
- Windows-консоль часто использует кодовую страницу (`cp866`, `cp1251`):
  русский текст из UTF-8 выводится «кракозябрами». Решение курса:
  логи и ключевые строки — **ASCII**; про кодировку консоли —
  раздел «Символ `\n` и кодировка консоли» в `th01/pitfalls.md`.
- SFML 3 использует `std::string`/`std::u32string` — заголовки окон задаются
  UTF-8 строками; особенностей встроенного рендеринга текста — тема th24.

### 5.4. Число → строка, строка → число

```cpp
std::string score = std::to_string(12345);   // "12345"
int v = std::stoi("42");                      // 42
int bad = std::stoi("abc");                   // throw std::invalid_argument
```

- `stoi`/`stof`/`stod` бросают исключения при неправильном вводе (th10);
  проверяйте пограничные случаи до преобразования или оборачивайте в
  `try/catch`.

## 6. Синтаксис

```cpp
#include <string>
#include <string_view>

std::string n = std::to_string(7);
std::string_view part(n.data(), 3);   // окно в n
if (n.find("xyz") != std::string::npos) { /* найдено */ }
```

- Заголовок окна с FPS: `"FPS: " + std::to_string(fps)` (ex01).
- Парсинг команд (ex04): `std::string_view token(line)`, разбиение по

## 10. Применение в песочницах

- Имена ресурсов, айди предметов — строки-ключи (`head`, `stone_1`).
- Сериализация сохранений (th33) строится на строках.
- Парсер команд из консоли/файла с `string_view` — без лишних аллокаций.

## 11. Взаимодействие с SFML

- `sf::Font::loadFromFile("path")` принимает строку/`std::filesystem::path`.
- Заголовок окна — `window.setTitle("...")`.
- Риски юникода в SFML-окнах и шрифтах — тема th24; пока достаточно ASCII
  в учебных примерах.

## 12. Типичные ошибки

- `s == "1" + s` — сложение неожиданных типов;
- `substr` в каждом вызове (лишние копии) вместо `string_view`;
- `string_view` на локальную временную строку;
- `stoi` без обработки ошибок;
- путаница «байты vs символы» в размере строки.

## 13. Подводные камни

- `find` возвращает `npos`, а не «-1»; сравнение `!= npos`;
- строка-литерал `""` — это `const char[N]`, не `std::string`;
- `std::string_view` может «не иметь» `\0` — не передавайте его туда, где
  ждут `const char*`, без `.data()` и длины.

## 14. Советы по проектированию

- Параметры «читать текст» — `std::string_view`; «хранить/владеть» —
  `std::string`.
- Конкатенацию в цикле делайте через `append` или `std::ostringstream`,
  а не `s = s + x;` (аллокация на каждой итерации; оптимизация — th53).
- В логи курса — ASCII, чтобы не зависеть от кодовой страницы консоли.
