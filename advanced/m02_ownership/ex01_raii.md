# m02_ownership/ex01_raii — RAII и scope guard

> **Модуль:** `m02_ownership` · **Сложность:** ★★★☆☆ · **Время:** 50–70 мин
> **Запуск:** `./run.ps1 m02_ownership/ex01_raii`

## Теория (кратко)

**RAII** (Resource Acquisition Is Initialization) — ресурс захватывается в
конструкторе, освобождается в деструкторе. Тогда при любом выходе из области
видимости (включая исключение) ресурс освобождается автоматически. Это фундамент
владения в C++: файлы, сокеты, мьютексы, GPU-хендлы, память.

| Свойство | Как обеспечивается |
|---|---|
| захват ресурса | конструктор |
| освобождение | деструктор |
| запрет копирования | `= delete` (или rule of 5, `ex02`) |
| освобождение при исключении | автоматический вызов деструкторов (unwinding) |
| «выполнить в конце» | scope guard |

## Синтаксис

```cpp
class File {
public:
    explicit File(const char* path) : handle_(std::fopen(path, "w")) {
        if (!handle_) { throw std::runtime_error("open failed"); }
    }
    ~File() { if (handle_) { std::fclose(handle_); } }   // osvobozhdenie

    File(const File&) = delete;                          // net kopirovaniya
    File& operator=(const File&) = delete;

    std::FILE* get() const noexcept { return handle_; }
private:
    std::FILE* handle_{};
};
```

## Подводные камни

- Деструктор должен быть `noexcept` по духу: бросать из него — `terminate`.
- RAII-объект, живущий дольше ресурса, которым владеет, — ошибка дизайна.
- Порядок разрушения обратен порядку создания (LIFO).
- «Ручной» `close()` где-то в коде ломает гарантию — освобождение должно быть
  только в деструкторе.

## Задача

В `ex01_raii.cpp`:

1. реализуйте RAII-обёртку `File` над `std::FILE*` (`tmpfile`/`fclose`);
2. запретите копирование;
3. напишите `ScopeGuard`, выполняющий лямбду в деструкторе;
4. продемонстрируйте порядок освобождения (LIFO) и освобождение при выходе;
5. покажите, что при исключении деструкторы всё равно вызываются.

## Где применяется

- Любое владение ресурсом: `std::vector`, `std::fstream`, `std::lock_guard`.
- Scope guard — откат транзакций, восстановление состояния, отписки от событий.
- Границы C-API (`fopen`, `SDL_CreateWindow`, `lua_close`) — оборачиваются в RAII.

Прогон печатает след открытия/закрытия и порядок срабатывания guard'ов;
завершается `0`.
