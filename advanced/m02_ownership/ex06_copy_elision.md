# m02_ownership/ex06_copy_elision — Копирующее опускание (RVO/NRVO)

> **Модуль:** `m02_ownership` · **Сложность:** ★★★☆☆ · **Время:** 40–60 мин
> **Запуск:** `./run.ps1 m02_ownership/ex06_copy_elision`

## Теория (кратко)

Компилятор вправе (а в некоторых случаях — **обязан**) сконструировать объект
сразу на месте назначения, без промежуточной копии/перемещения:

- **RVO** (Return Value Optimization) — возврат временного (`prvalue`) объекта.
- **NRVO** — возврат именованного локального объекта.
- **Copy elision** — при инициализации из временного.

С C++17 RVO для `prvalue` **гарантирован** (это уже не оптимизация, а правило
языка). NRVO — нет, но компиляторы его делают.

| Случай | Гарантировано | Копий/перемещений |
|---|---|---|
| `return Counted(1);` | да (C++17) | 0 |
| `Counted c; return c;` | нет (NRVO) | обычно 0 |
| `return std::move(c);` | нет | 1 перемещение |

## Синтаксис

```cpp
Counted make_prvalue() { return Counted(1); }        // RVO
Counted make_named()   { Counted c(2); return c; }   // NRVO
Counted make_move()    { Counted c(3); return std::move(c); }  // move, bez elision

Counted a = make_prvalue();   // objekt sozdan srazu v 'a'
```

## Подводные камни

- `return std::move(local);` **запрещает** NRVO — это антипаттерн.
- `std::move_if_noexcept` выбирает копирование, если move не `noexcept` (важно
  для контейнеров).
- Не «помогайте» компилятору `std::move` там, где и так сработает elision.
- Elision меняет наблюдаемое поведение (счётчики конструкторов): тесты не должны
  полагаться на число копий там, где elision не гарантирован.

## Задача

В `ex06_copy_elision.cpp`:

1. реализуйте `Counted` со счётчиками конструкторов/копий/перемещений;
2. напишите `make_prvalue`, `make_named`, `make_move`;
3. для каждого случая сбросьте счётчики, вызовите и напечатайте числа;
4. убедитесь, что `prvalue`-случай делает **0 копий/перемещений**;
5. покажите, что `return std::move(local)` даёт перемещение.

## Где применяется

- Возврат больших объектов из функций без копий — норма современного C++.
- Понимание, почему `return value;` (не `return std::move(value);`) — правильно.
- Проектирование фабрик и API вокруг value-семантики.

## Проверка

Прогон печатает счётчики по каждому случаю; завершается `0`.
