# m00_tooling/ex03_debug_sanitizers — Отладка: санитайзеры и проверки

> **Модуль:** `m00_tooling` · **Сложность:** ★★☆☆☆ · **Время:** 40–60 мин
> **Запуск:** `./run.ps1 m00_tooling/ex03_debug_sanitizers`

## Теория (кратко)

Большинство «странных» падений C++-программ — это неопределённое поведение (UB):
выход за границу массива, разыменование висячего указателя, переполнение знакового
целого, гонки. Компилятор вправе делать с UB что угодно, поэтому его нужно
**ловить инструментами**, а не глазами.

| Инструмент | Что находит |
|---|---|
| AddressSanitizer (`-fsanitize=address`) | выход за границу, use-after-free, утечки |
| UndefinedBehaviorSanitizer (`-fsanitize=undefined`) | переполнения, сдвиги, алиасинг |
| `_GLIBCXX_ASSERTIONS` | проверки прекондий в контейнерах STL (`operator[]`, итераторы) |
| `_GLIBCXX_DEBUG` | более тяжёлый «отладочный STL» (меняет ABI) |

> **Важно для MinGW.** В MinGW-GCC нет `libasan`/`libubsan`, поэтому
> `-fsanitize=...` не линкуется. На Windows используем `_GLIBCXX_ASSERTIONS`; для
> полноценных ASan/UBSan нужны Linux/WSL или clang. Скрипт `-Sanitize` сам
> подбирает режим.

## Синтаксис

```cpp
std::vector<int> v{1, 2, 3};
v[3];  // UB: индекс вне диапазона
       // с _GLIBCXX_ASSERTIONS -> сработает assert и программа аварийно завершится
```

Условная компиляция «сломанного» демо-кода:

```cpp
#ifdef DEMO_UB
    // намеренная ошибка
#else
    // корректный код
#endif
```

## Подводные камни

- `_GLIBCXX_DEBUG` меняет ABI: нельзя смешивать с обычными объектными файлами и
  прекомпилированными библиотеками.
- ASan замедляет программу в ~2 раза и увеличивает память — это отладочный
  инструмент, а не релизный режим.
- Санитайзер ловит только то, что реально выполнилось: «мертвую» ветку он не
  проверит, нужен тест/фаззинг.

## Задача

В `ex03_debug_sanitizers.cpp` функция `sum_first_n` в обычном режиме корректна.
За макросом `DEMO_UB` спрятана намеренная ошибка (чтение на один элемент за
границей). Выполните:

```powershell
# корректный прогон
./run.ps1 m00_tooling/ex03_debug_sanitizers

# демонстрация: проверки STL должны поймать выход за границу
./run.ps1 m00_tooling/ex03_debug_sanitizers -Sanitize -Extra '-DDEMO_UB'
```

Второй запуск должен аварийно завершиться с диагностикой (`assert`), а не
молча выдать неверный результат.

## Где применяется

- Регулярные ASan/UBSan-прогоны в CI — дешёвая страховка от «плавающих» падений.
- `_GLIBCXX_ASSERTIONS` включают в отладочных сборках шутеров/движков, где важна
  скорость итерации.
- Fuzzing (libFuzzer/AFL) + ASan — стандартный способ искать баги в парсерах и
  декодерах.

## Проверка

- Обычный прогон печатает сумму и `return 0`.
- Прогон с `-Sanitize -DDEMO_UB` завершается ненулевым кодом с сообщением от
  проверок STL.
