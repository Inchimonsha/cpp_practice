# m00_tooling/ex02_compiler_flags — Предупреждения и атрибуты

> **Модуль:** `m00_tooling` · **Сложность:** ★☆☆☆☆ · **Время:** 30–40 мин
> **Запуск:** `./run.ps1 m00_tooling/ex02_compiler_flags`

## Теория (кратко)

Компилятор знает о программе больше, чем кажется: неиспользуемые переменные,
неявные сужения, перекрытие имён, забытый `break`. Уровень предупреждений —
часть контракта кода. В этом курсе базовый набор такой:

| Флаг | Что ловит |
|---|---|
| `-Wall -Wextra` | основной набор опечаток и подозрительного кода |
| `-Wpedantic` | отклонения от стандарта |
| `-Wshadow` | перекрытие имён во вложенной области видимости |
| `-Wconversion` / `-Wsign-conversion` | неявные сужения и смену знака |
| `-Werror` | «лечить, а не игнорировать»: делает предупреждение ошибкой |

Атрибуты выражают намерение прямо в коде и читаются компилятором и
статическими анализаторами.

## Синтаксис

```cpp
[[nodiscard]] int compute();          // результат игнорировать нельзя
void log([[maybe_unused]] int level); // параметр пока не используется
[[deprecated("use parse_v2")]] void parse_v1();

switch (x) {
    case 1: [[fallthrough]];          // явное «проваливание» намеренно
    case 2: break;
    default: break;
}
```

Приведение для `-Wconversion`:

```cpp
int n = static_cast<int>(v.size());   // вместо неявного size_t -> int
```

## Подводные камни

- `-Wconversion` очень шумный на существующем коде; включайте его точечно и
  вместе с `-Werror` в CI, а не в каждом экспериментальном прогоне.
- `[[nodiscard]]` на конструкторе бессмысленен; на типе (`class [[nodiscard]]`)
  он действует на все функции, возвращающие этот тип.
- `[[fallthrough]]` обязателен только для «непустого» `case` без `break`.

## Задача

В `ex02_compiler_flags.cpp` написана чистая утилита `parse_level`. Доведите её
так, чтобы она собиралась **без единого предупреждения** в строгом режиме:

```powershell
./run.ps1 m00_tooling/ex02_compiler_flags -Extra '-Werror -Wconversion -Wsign-conversion'
```

Для этого используйте явные приведения и корректные типы. Дополнительно
добавьте `[[nodiscard]]` к функции, возвращающей результат, который нельзя
игнорировать, и `[[maybe_unused]]` к необязательному параметру.

## Где применяется

- `[[nodiscard]]` — почти в каждом публичном API реальных библиотек: забытый
  результат `read()`/`try_lock()`/`parse()` — классический баг.
- `-Wconversion` — обязателен в коде, работающем с длинами буферов, индексами,
  битовыми масками (сеть, сериализация, графика).
- `[[deprecated]]` — управляемое вытеснение устаревшего API без ломающих
  изменений.

## Проверка

Обычный прогон печатает разбор нескольких уровней; строгий прогон (с `-Werror`)
завершается успешно — предупреждений нет.
