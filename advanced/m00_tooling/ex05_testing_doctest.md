# m00_tooling/ex05_testing_doctest — Микро-фреймворк и unit-тесты

> **Модуль:** `m00_tooling` · **Сложность:** ★★☆☆☆ · **Время:** 40–60 мин
> **Запуск:** `./run.ps1 m00_tooling/ex05_testing_doctest`

## Теория (кратко)

Тест — это функция, которая проверяет наблюдаемое поведение и падает при
нарушении. Для быстрой проверки не нужна внешняя библиотека: хватает реестра
тестов и нескольких макросов. Зрелые фреймворки (doctest, Catch2, GoogleTest)
устроены так же, но богаче.

Схема «регистрация + запуск»: макрос `TEST(name)` создаёт функцию и объект-
регистратор, который кладёт её в глобальный список. `main` перебирает список и
возвращает ненулевой код при провале.

## Синтаксис

```cpp
#define TEST(name)                                                  \
    static void name();                                             \
    [[maybe_unused]] static microtest::Registrar reg_##name(#name, name); \
    static void name()

TEST(adds) { EXPECT(add(2, 2) == 4); }
```

| Часть | Назначение |
|---|---|
| `#name` | строковое имя теста из идентификатора |
| `reg_##name` | вставка токенов: уникальное имя регистратора |
| `EXPECT(cond)` | фиксирует провал, но продолжает тест |
| `__FILE__`, `__LINE__` | локация провала в диагностике |

## Подводные камни

- Тест должен зависеть только от тестируемого кода, а не от вывода в консоль.
- `EXPECT` печатает и продолжает; `REQUIRE`-семантика (прервать) нужна, если
  следующие проверки небезопасны после провала.
- Тесты не должны иметь общего изменяемого состояния между собой.

## Задача

Доведите `ex05_testing_doctest.cpp` так, чтобы:

1. микро-фреймворк корректно считал провалы и возвращал код `0/1`;
2. покрыты функции `add`, `clamp_range`, `is_even` из `main`-приложения;
3. `ctest`-подобный вывод печатал `PASSED`/`FAILED` и число провалов;
4. при намеренно неверном ожидании программа возвращала `1`.

## Где применяется

- Юнит-тесты «чистой» логики (математика, парсинг, правила) — без окна и
  ресурсов.
- Doctest/Catch2 подключаются одним заголовком в существующий проект; иногда
  тесты компилируются в отдельную цель.
- Тот же каркас используют для быстрых экспериментов: написал гипотезу —
  проверил тестом.

## Проверка

`./run.ps1 m00_tooling/ex05_testing_doctest` печатает список тестов, итог и
завершается `0`. Если поменять ожидание на неверное — завершается `1`.
