# m05_errors/ex04_error_strategies — Стратегии обработки ошибок

> **Модуль:** `m05_errors` · **Сложность:** ★★★☆☆ · **Время:** 50–70 мин
> **Запуск:** `./run.ps1 m05_errors/ex04_error_strategies`

## Теория (кратко)

Единого «правильного» механизма нет — выбирайте по характеру ошибки и месту в
системе:

| Стратегия | Когда уместна | Минусы |
|---|---|---|
| **исключения** | исключительные, «далёкие» сбои; нельзя игнорировать | контроль потока, стоимость на горячем пути |
| **`optional`** | «нет значения» без причины | нет информации об ошибке |
| **`expected`/`error_code`** | ожидаемые ошибки, границы ABI/hot-path | многословность обработки |
| **контракты (`pre`/`post`, C++26)** | ошибки **программиста** (инварианты) | не для пользовательских ошибок |
| **assert/`abort`** | «не должно случиться» | в релизе отключают |

Общее правило: **ожидаемые** ошибки — значениями (`expected`), **исключительные**
— исключениями, **нарушения инвариантов** — контрактами/assert.

## Синтаксис

```cpp
// slicer dlya sravneniya odnoj operacii raznymi sposobami
double divide_throws(double a, double b);                        // throw
std::optional<double> divide_opt(double a, double b);            // optional
std::expected<double, std::string> divide_expected(double, double);
```

## Подводные камни

- Не используйте исключения для **ожидаемого** потока (парсинг ввода, «не
  найдено») — это дорого и затрудняет контроль.
- Не глотайте `error_code` молча: проверяйте возврат.
- Контракты не заменяют обработку пользовательских ошибок: нарушение контракта —
  это баг, а не входные данные.
- Держите единый стиль в границах модуля; смешение без причины — путаница.

## Задача

В `ex04_error_strategies.cpp`:

1. реализуйте деление тремя способами: исключением, `optional`, `expected`;
2. вызовите успешный и ошибочный сценарии для каждого;
3. выведите диагностику (тип и сообщение);
4. опишите в комментарии (и печати), какую стратегию и почему выбрали бы;
5. при наличии — покажите контракт как «preview» для инварианта.

## Где применяется

- Библиотеки с ABI (`expected`/коды) vs внутренние слои (исключения).
- Игровые/сетевые системы с жёсткими бюджетами кадра (без исключений на
  hot-path).
- Публичные API: документированная стратегия ошибок.
