# m05_errors/ex02_noexcept — `noexcept` и рост контейнеров

> **Модуль:** `m05_errors` · **Сложность:** ★★★☆☆ · **Время:** 40–60 мин
> **Запуск:** `./run.ps1 m05_errors/ex02_noexcept`

## Теория (кратко)

Спецификатор `noexcept` обещает, что функция не бросает исключений. Это важно
для производительности: при росте `std::vector` контейнер **перемещает**
элементы только если перемещающий конструктор `noexcept`; иначе — **копирует**,
чтобы сохранить strong-гарантию. `std::move_if_noexcept` инкапсулирует это
решение.

| Проверка | Смысл |
|---|---|
| `is_nothrow_move_constructible_v<T>` | можно ли перемещать без риска |
| `is_nothrow_copy_constructible_v<T>` | безопасна ли копия |
| `noexcept(expr)` | «обещает ли» выражение не бросать |

## Синтаксис

```cpp
struct T {
    T(T&& other) noexcept;          // razreshaet peremeshchenie v vector
};

static_assert(std::is_nothrow_move_constructible_v<T>);

template <class U>
U&& move_if_noexcept(U& x) noexcept;  // move, esli bezopasno; inache copy
```

## Подводные камни

- Забыли `noexcept` на move → контейнеры копируют при росте (потеря
  производительности).
- `noexcept` — это обещание: если функция всё же бросит, вызовется
  `std::terminate`.
- `noexcept(false)` — явный «может бросать» (по умолчанию).
- Move-конструктор следует помечать `noexcept`, если он действительно не бросает
  (обычно так и есть для move).

## Задача

В `ex02_noexcept.cpp`:

1. заведите тип с `noexcept`-move и тип с возможно-бросающим move (плюс копия);
2. наполните `std::vector` каждым и посчитайте копии/перемещения при росте;
3. покажите, что у `noexcept`-типа копий **нет**, у второго — есть;
4. выведите `is_nothrow_move_constructible_v` для обоих;
5. покажите поведение `noexcept(expr)`.

## Где применяется

- Проектирование типов для хранения в контейнерах без лишних копий.
- Гарантии в API (например, `swap`, деструкторы, move-операции).
- Оптимизация конфигурируется компилятором на основе этих обещаний.
