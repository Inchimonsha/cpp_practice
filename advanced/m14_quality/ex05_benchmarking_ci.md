# m14_quality/ex05_benchmarking_ci — микробенчмарк и регрессионный порог

> Модуль m14_quality · Сложность ★★★ · C++23 · Запуск: `./run.ps1 m14_quality/ex05_benchmarking_ci`
>
> **Время выполнения изменяется** от запуска к запуску — это бенчмарк.
> Проверяется корректность результата и прохождение «гейта», а не сами мс.

## Теория

**Микробенчмарк** измеряет производительность небольшой функции. Ключевые
приёмы достоверности:

- **Прогрев** и несколько замеров, затем **медиана** (устойчивее среднего к
  выбросам);
- **отключение оптимизации результата** (компилятор не должен выбросить вызов
  «за ненадобностью»);
- **одинаковые условия** для сравниваемых вариантов;
- **регрессионный гейт**: если время хуже бюджета/базлайна — сборка CI падает.

Пример сравнивает две функции построения строки: `+=` (перевыделение буфера) и
`reserve` (одно выделение). Разница видна, но на малых объёмах мала.

Фреймворки: **Google Benchmark**, **Catch2 BENCHMARK**, **nanobench**.

## Синтаксис

```cpp
template <class Function>
double median_ms(Function function, int samples) {
    std::vector<double> times;
    for (int s = 0; s < samples; ++s) {
        const auto start = std::chrono::steady_clock::now();
        volatile std::size_t sink = function().size();   // ne dat' optimizirovat'
        static_cast<void>(sink);
        const auto end = std::chrono::steady_clock::now();
        times.push_back(std::chrono::duration<double, std::milli>(end - start).count());
    }
    std::sort(times.begin(), times.end());
    return times[times.size() / 2];                       // mediana
}

const bool gate = naive_ms < budget_ms;                   // regressiohnyy porog
```

## Подводные камни

- **Оптимизация убирает замеряемое**: без «стока» (`volatile`, `benchmark::DoNotOptimize`)
  компилятор выбросит работу и время будет ~0.
- **Слишком мелкая задача**: шум планировщика/таймера превышает сигнал;
  увеличьте объём или повторяйте в цикле.
- **Один замер** ничего не значит: берите медиану/минимум из многих.
- **Изменчивая среда**: CPU-троттлинг, фоновая нагрузка, разные контейнеры CI —
  сравнивайте **относительно** и фиксируйте окружение.
- **Порог-гейт должен быть устойчив**: слишком строгий бюджет даёт «флейки» в
  CI; закладывайте запас.
- Бенчмарк **не проверяет корректность** сам по себе — сверяйте результат
  (`naive == reserved` здесь).

## Задача

Измерить медиану времени построения строки из 20 000 чисел двумя способами
(`+=` и `reserve`), вывести медианы и ускорение, применить регрессионный гейт
по бюджету 50 мс и проверить равенство результатов.

## Где применяется

- CI-контроль производительности, выбор алгоритма/структуры, поиск деградаций
  после рефакторинга, профилирование горячих путей.

## Проверка

Вывод: `count = 20000, samples = 15`, `naive    = ... bytes, median = ... ms`,
`reserved = ... bytes, median = ... ms`, `speedup = ...x`,
`regression gate (< 50 ms): pass`, `benchmarking ci done`. Время произвольно;
код возврата `0`, если результаты равны и гейт пройден, иначе `1`.
