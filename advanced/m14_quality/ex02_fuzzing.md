# m14_quality/ex02_fuzzing — мутационный фаззинг с обратной связью по покрытию

> Модуль m14_quality · Сложность ★★★ · C++23 · Запуск: `./run.ps1 m14_quality/ex02_fuzzing`

## Теория

**Фаззинг** — подача на вход программы большого числа случайных/искажённых
данных ради поиска падений (багов памяти, зависаний, исключений). Виды:

- **Чёрный ящик**: случайные входы без знания программы.
- **Мутационный, с обратной связью по покрытию** (coverage-guided, как
  libFuzzer/AFL): если вход открыл **новую ветвь/путь**, он сохраняется в
  **корпус** и служит основой для дальнейших мутаций. Так фаззер «проникает»
  глубже в логику.

Модель: цель `target` отмечает пройденные ветви в счётчике `Coverage`. Фаззер
мутирует элемент корпуса (замена/вставка/удаление символа), запускает цель,
и при новом покрытии добавляет вход в корпус. Краши перехватываются внешним
`try/catch` (в реальности — сигналы/ASan/UBSan + `abort`).

## Синтаксис

```cpp
struct Coverage { std::array<bool, 8> branches{}; int count() const; };

int target(std::string_view input, Coverage& cov) {
    cov.branches[0] = true;
    if (input.empty()) { cov.branches[1] = true; return 0; }
    // ... else if po klassam simvolov, coverage.branches[3..6] ...
}

std::mt19937 generator(0xC0FFEEu);
for (int i = 0; i < 20000; ++i) {
    std::string candidate = mutate(corpus[generator() % corpus.size()], generator);
    Coverage local;
    target(candidate, local);
    if (new_coverage(global, local)) corpus.push_back(candidate);   // feedback
}
```

## Подводные камни

- **Недетерминированный seed** затрудняет воспроизведение — фиксируйте и
  логируйте seed/corpus.
- **Нет обратной связи** → фаззер застревает у мелких входов и не проходит
  проверки длины/формата.
- **Счётчик покрытия ≠ реальное покрытие**: ветви считаются «инструментом»; их
  нужно держать в синхроне с кодом цели.
- **Краши нужно ловить**: без ASan/UBSan ошибки памяти могут не проявляться как
  падение и пройти незамеченными. Подключайте санитайзеры на этапе CI.
- **Рост корпуса**: хранение всех «интересных» входов требует памяти; реальные
  фаззеры дедуплицируют и ограничивают корпус.
- Фаззинг **не доказывает** отсутствие багов — он лишь повышает шанс их найти.

## Задача

Собрать мини-фаззер: цель отмечает пройденные ветви, фаззер мутирует корпус из
`{"", "a", "1", "Z9"}` за 20000 итераций, добавляет входы с новым покрытием,
считает краш и итоговое покрытие.

## Где применяется

- Парсеры (JSON/HTTP/архивы), декодеры изображений/кодеков, драйверы,
  криптографические библиотеки, компиляторы и языковые рантаймы.

## Проверка

Вывод: `fuzzing: 20000 iterations, corpus reached ...`,
`branch coverage = 8/8`, `crashes = 0`, `fuzzing done`. Код возврата `0`, если
крашей нет и покрыто не менее 6 ветвей, иначе `1`.

## Решение

См. `ex02_fuzzing.cpp`. Реальные инструменты: **libFuzzer** (Clang, требует
