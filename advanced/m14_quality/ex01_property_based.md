# m14_quality/ex01_property_based — тестирование свойств и сжатие контрпримера

> Модуль m14_quality · Сложность ★★★ · C++23 · Запуск: `./run.ps1 m14_quality/ex01_property_based`

## Теория

**Property-based testing** проверяет не отдельные примеры, а **свойства**
(инварианты), которые должны выполняться для *всех* входов. Фреймворк
генерирует случайные входы, а при нарушении — **сжимает** (shrinking)
контрпример к минимальному, чтобы баг было легко понять.

Проверяемые здесь свойства:

- **инволюция разворота**: `reverse(reverse(xs)) == xs`;
- **упорядоченность сортировки**: `is_sorted(sort(xs))`;
- **намеренно ложное** свойство `x < 100` — на нём показывается shrinking.

Источник случайности — `std::mt19937` с **фиксированным seed**: тест
воспроизводим (одинаковые контрпримеры при каждом запуске). Реальные
фреймворки: **QuickCheck** (Haskell), **Hypothesis** (Python), **RapidCheck**
(C++), **Catch2** generators.

Shrinking: получив падающий вход, многократно пытаются «уменьшить» его
(деление пополам, вычитание единицы), сохраняя падение, пока не достигнут
минимума.

## Синтаксис

```cpp
std::mt19937 generator(12345);                       // fiksirovannyy seed
std::uniform_int_distribution<int> value_dist(-1000, 1000);
auto values = random_vector(generator, value_dist);
assert(reverse_copy(reverse_copy(values)) == values);   // svoystvo

// shrinking k minimal'nomu kontrprimeru:
while (progress) {
    if (fails(counterexample / 2)) { counterexample /= 2; progress = true; continue; }
    if (fails(counterexample - 1)) { --counterexample; progress = true; }
}
```

## Подводные камни

- **Нефиксированный seed** делает падения невоспроизводимыми. Печатайте seed
  и найденный контрпример в отчёт.
- **Слабые генераторы** не покрывают границы (пустой ввод, ноль, переполнение) —
  комбинируйте случайные значения с «краевыми» фикстурами.
- **Свойство ≠ тест-пример**: плохое свойство (`f(x)==f(x)`) всегда проходит и
  бесполезно. Формулируйте независимые инварианты (например, сравнение с
  эталонной реализацией).
- **Shrinking должен сохранять падение**; наивное «просто уменьшить» может
  увести на проходящий вход и «спрятать» баг.
- Стоимость: 200 итераций в примере — демонстрация; в реальности генерируют
  тысячи и ограничивают время.

## Задача

Проверить два истинных свойства (инволюция разворота, упорядоченность
сортировки) на 200 случайных векторах и найти сжатый контрпример для ложного
свойства `x < 100`. Вывести результаты.

## Где применяется

- Компиляторы и парсеры (idempotency), сериализация (round-trip),
  структуры данных (инварианты кучи/дерева), численные алгоритмы.

## Проверка

Вывод: `property reverse-involution: passed (200 cases)`,
`property sort-ordered: passed (200 cases)`,
`property value < 100: FAILED, shrunk counterexample = 100`,
`property based done`. Код возврата `0` при совпадении, иначе `1`.

## Решение

См. `ex01_property_based.cpp`. Контрпример сжат до порога `100` — частый
признак «пограничной» ошибки.
