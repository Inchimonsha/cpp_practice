# m12_parallel_gpu/ex05_false_sharing — ложное разделение (false sharing)

> Модуль m12_parallel_gpu · Сложность ★★★ · C++23 · Запуск: `./run.ps1 m12_parallel_gpu/ex05_false_sharing`
>
> **Время выполнения изменяется** от запуска к запуску — это бенчмарк.
> Проверяются только суммы счётчиков.

## Теория

Процессоры обмениваются памятью **линиями кэша** (обычно 64 байта), а не
отдельными байтами. Если два потока пишут в **разные** переменные, лежащие в
одной линии кэша, когерентность заставляет линию «прыгать» между ядрами. Это
**false sharing** — ложное разделение: данные не общие, но производительность
падает, будто они общие.

- Потоки пишут в **соседние** `std::atomic<long long>` — они попадают в одну
  линию → кэш-пинг-понг.
- Если каждый счётчик **выровнять** на начало своей линии (`alignas(64)`),
  потоки перестают мешать друг другу → кратный рост скорости.

Это следствие правила: минимизируйте совместное использование, а когда данные
меняются разными потоками — разносите их по линиям кэша.

## Синтаксис

```cpp
// Ploxo: sosedi v odnoy linii ke'sha
std::vector<std::atomic<long long>> packed(threads);

// Horosho: kazhdyy schetchik na svoyey linii
struct alignas(64) PaddedCounter { std::atomic<long long> value{0}; };
std::vector<PaddedCounter> padded(threads);

auto t0 = std::chrono::steady_clock::now();
{
    std::vector<std::jthread> pool;
    for (unsigned t = 0; t < threads; ++t)
        pool.emplace_back([&]{ for (int i = 0; i < N; ++i)
                                   padded[t].value.fetch_add(1, std::memory_order_relaxed); });
}
auto ms = std::chrono::duration<double, std::milli>(
              std::chrono::steady_clock::now() - t0).count();
```

## Подводные камни

- **`alignas(64)` — размер линии у конкретной архитектуры** может быть иным;
  узнавайте его (`/proc/cpuinfo` на Linux, `GetLogicalProcessorInformation` на
  Windows) или берите безопасные 64.
- **`std::atomic` не гарантирует выравнивания по линии** — только по границе
  самого типа; отсюда необходимость `alignas`.
- **Измерения шумны**: фоновая нагрузка, частоты, тепловой троттлинг,
  планировщик. Давайте несколько прогонов и сравнивайте медиану, а не один
  замер.
- **Ложное разделение бывает и на чтении-записи** соседних полей структуры —
  не только между счётчиками.
- Не путайте с **истинным** разделением (data race): это ошибка
  корректности; false sharing — только производительность.
- В примере время сравнивается «на глаз»; для строгих выводов нужен
  повтор с усреднением, изоляция ядер и отключение турбо-режимов.

## Задача

Запустить 4 потока, каждый делает 2 000 000 инкрементов своего счётчика: для
упакованного (соседние `atomic`) и для выровненного (`alignas(64)`) вариантов.
Вывести суммы и время обоих вариантов.

## Где применяется

- Высоконагруженные серверы (счётчики, пулы), игровые движки (покадровые
  структуры по потокам), научные коды, системы реального времени.

## Проверка

Вывод: `threads = 4, iterations = 2000000`, `packed total = 8000000  elapsed = ... ms`,
`padded total = 8000000  elapsed = ... ms`, `false sharing done`. Время
произвольно; код возврата `0`, если обе суммы равны `8000000`, иначе `1`.

## Решение

См. `ex05_false_sharing.cpp`. Наблюдается заметное превосходство `padded`
(например, десятки против сотен миллисекунд) — прямое следствие выравнивания
по линии кэша.
