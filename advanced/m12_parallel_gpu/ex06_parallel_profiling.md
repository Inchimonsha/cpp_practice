# m12_parallel_gpu/ex06_parallel_profiling — измерение ускорения (speedup)

> Модуль m12_parallel_gpu · Сложность ★★★ · C++23 · Запуск: `./run.ps1 m12_parallel_gpu/ex06_parallel_profiling`
>
> **Время выполнения изменяется** от запуска к запуску — это бенчмарк.
> Проверяется только равенство результатов.

## Теория

Эффект параллелизма измеряют **ускорением** (speedup):

```
S(p) = T(1) / T(p)
```

где `T(1)` — время последовательной версии, `T(p)` — параллельной на `p`
потоках. Идеал `S(p) = p`, реальность ниже из-за:

- **Последовательной доли** (закон Амдала): `S(p) ≤ 1 / (s + (1-s)/p)`, где
  `s` — непараллелизуемая часть.
- **Накладных расходов**: запуск потоков, синхронизация, разделяемая память.
- **Пропускной способности памяти**: если узкое место — память, добавление ядер
  помогает мало (memory-bound задача против CPU-bound).
- **Дисбаланса нагрузки**: одни потоки простаивают в ожидании других.

Методика измерения: одна и та же задача (здесь — сумма `sqrt(i)` для 20 млн
чисел), прогрев, замер `steady_clock`, сравнение. Для честного результата
нужно несколько прогонов и медиана, отключение частотных турбо-режимов.

## Синтаксис

```cpp
double parallel_sum(std::size_t count, unsigned workers) {
    std::vector<double> partial(workers, 0.0);
    {
        std::vector<std::jthread> pool;
        for (unsigned w = 0; w < workers; ++w)
            pool.emplace_back([&partial, count, workers, w] {
                double acc = 0.0;
                for (std::size_t i = w + 1; i <= count; i += workers)
                    acc += std::sqrt(static_cast<double>(i));
                partial[w] = acc;                 // pomecheno: kazhdyy potok - svoy element
            });
    }
    double total = 0.0;
    for (double v : partial) total += v;
    return total;
}

const double speedup = serial_ms / parallel_ms;
std::println("speedup = {:.2f}x", speedup);
```

## Подводные камни

- **Недетерминированное время**: результат измерения зависит от машины и
  загрузки; в тестах проверяйте корректность, а не порог по времени.
- **`hardware_concurrency()` может вернуть 0** — обработайте это.
- **Ложное и истинное разделение** записи в `partial[worker]`: здесь потоки
  пишут в разные элементы; при узких интервалах возможно false sharing
  (см. `ex05`).
- **Компилятор может оптимизировать** тривиальную работу — берите достаточно
  тяжёлую нагрузку или используйте `volatile`/зависимости по данным.
- **Накладные расходы на мелких задачах** сведут ускорение к <1; параллелизм
  оправдан при достаточном объёме работы.
- Сравнивайте **одну и ту же** работу: serial и parallel должны считать одно
  и то же (здесь — обе суммы `sqrt`).

## Задача

Измерить время последовательной и параллельной (по числу ядер) суммы
`sqrt(i)` для 20 млн чисел, вывести оба времени и ускорение. Проверить, что
результаты совпадают в пределах погрешности.

## Где применяется

- Оптимизация производительности, бенчмаркинг, capacity planning, оценка
  масштабируемости сервисов, отчётность по SLA.

## Проверка

Вывод: `workers = N, count = 20000000`, `serial   = ...  elapsed = ... ms`,
`parallel = ...  elapsed = ... ms`, `speedup = X.XXx`,
`parallel profiling done`. Время произвольно; код возврата `0`, если суммы
совпадают с точностью `1e-6`, иначе `1`.

## Решение

См. `ex06_parallel_profiling.cpp`. На 12 ядрах типичное ускорение — примерно
2–4× (зависит от памяти и накладных расходов), что иллюстрирует разрыв между
идеальным `S(p)=p` и реальностью.
