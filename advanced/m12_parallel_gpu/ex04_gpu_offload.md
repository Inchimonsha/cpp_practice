# m12_parallel_gpu/ex04_gpu_offload — модель выноса вычислений на устройство

> Модуль m12_parallel_gpu · Сложность ★★★ · C++23 · Запуск: `./run.ps1 m12_parallel_gpu/ex04_gpu_offload`

## Теория

GPU-вычисления строятся по схеме **host → device → kernel → host**:

1. **Память**. У GPU отдельная память (device memory). Данные копируются на
   устройство (`memcpy host->device`) и обратно.
2. **Ядро (kernel)**. Одна функция, исполняемая *каждым* вычислительным
   потоком (work-item). Поток узнаёт свой индекс и обрабатывает свои элементы.
3. **Запуск (launch)**. Ядро запускается **сеткой** (grid) из **блоков**
   (block/thread-group), в блоке — несколько потоков. Это SPMD-модель
   (single program, multiple data).

Промышленные API: **CUDA** (NVIDIA), **HIP** (AMD), **OpenCL** (кроссплатформа),
**SYCL** (стандартизуемый C++ поверх OpenCL/CUDA), **C++ AMP** (исторический).
В этом окружении реального GPU-рантайма нет, поэтому пример **моделирует**
архитектуру: сетка блоков исполняется пулом потоков, каждый блок обрабатывает
свой диапазон индексов. Так демонстрируется именно модель offload, а не
ускорение на железе.

## Синтаксис

```cpp
template <class Kernel>
void launch_kernel(std::size_t n, std::size_t block_size, Kernel kernel) {
    const std::size_t blocks = (n + block_size - 1) / block_size;
    std::vector<std::jthread> workers;
    for (std::size_t block = 0; block < blocks; ++block) {
        workers.emplace_back([&kernel, block, block_size, n] {
            const std::size_t begin = block * block_size;
            const std::size_t end = std::min(begin + block_size, n);
            for (std::size_t i = begin; i < end; ++i) kernel(i);   // telo yadra
        });
    }
}

launch_kernel(count, block_size, [&](std::size_t i) {
    device.y[i] = scale * device.x[i] + device.y[i];   // axpy
});
```

## Подводные камни

- **Асинхронность**. Реальные запуски асинхронны; нужно синхронизироваться
  (`cudaDeviceSynchronize`/`clFinish`) перед чтением результата.
- **Границы**. Последний блок часто неполный — индексация должна быть
  безопасной (`std::min(begin+block_size, n)`).
- **Латентность копирования**. Пересылка host↔device дорогая; минимизируйте
  число копирований и держите данные на устройстве.
- **Разделяемая память и гонки**. Внутри блока потоки могут использовать
  быструю `shared`-память, но нужна барьерная синхронизация; гонки на device
  приводят к неверным результатам без ошибок времени выполнения.
- **Оптимизация ядра**: ветвления резко снижают эффективность (SIMT);
  выравнивайте доступ к памяти (coalescing).
- Модель без GPU **не измеряет** ускорение — она объясняет структуру кода;
  перенос на реальный API меняет только строки запуска/копирования.

## Задача

Смоделировать offload: загрузить `x` и `y` на устройство, запустить ядро
`axpy` (`y = 2*x + y`) сеткой 4 блока × 2 потока, скопировать результат
обратно и вывести его. Ожидаемый результат: `2 4 6 8 10 12 14 16`.

## Где применяется

- Машинное обучение (тензорные операции), научные расчёты, рендеринг,
  криптография, обработка изображений/видео в реальном времени.

## Проверка

Вывод: `simulated device: 8 elements, 4 blocks x 2 threads`,
`memcpy host->device: x[8], y[8]`, `launch axpy kernel: y = 2 * x + y`,
`memcpy device->host: y[8]`, `result = 2 4 6 8 10 12 14 16`,
`gpu offload (simulated) done`. Код возврата `0` при совпадении, иначе `1`.

## Решение

См. `ex04_gpu_offload.cpp`. Реального рантайма нет — сетка эмулируется
потоками; детерминизм обеспечивается тем, что элементы не пересекаются.
