# m12_parallel_gpu/ex01_parallel_stl — политики выполнения и параллельные алгоритмы

> Модуль m12_parallel_gpu · Сложность ★★ · C++23 · Запуск: `./run.ps1 m12_parallel_gpu/ex01_parallel_stl`

## Теория

Стандартная библиотека даёт **execution policies**: алгоритму можно передать
первым аргументом политику, и он вправе распараллелить работу.

| Политика | Смысл |
|---|---|
| `std::execution::seq` | последовательно (значение по умолчанию) |
| `std::execution::par` | параллельно, по одному потоку на элемент |
| `std::execution::par_unseq` | параллельно + векторизуемо (можно переупорядочивать, сливать) |

Политику понимают десятки алгоритмов: `for_each`, `transform`, `reduce`,
`transform_reduce`, `count_if`, `sort`, `find`, `inclusive_scan` и др.
Ключевой паттерн — **map-reduce**: `transform_reduce` (отображение + свёртка).

Бэкенд. Реализация `libstdc++` при наличии TBB использует её пул; без TBB
работает **последовательный бэкенд** — API есть, ускорения нет. Проверить
можно макросом `_PSTL_PAR_BACKEND_TBB`. Именно это наблюдается на текущем
тулчейне (TBB не установлен), поэтому пример демонстрирует корректность, а не
ускорение.

## Синтаксис

```cpp
std::transform(std::execution::par, in.begin(), in.end(), out.begin(), f);

long long sum = std::reduce(std::execution::par, out.begin(), out.end(), 0LL);

long long mapped = std::transform_reduce(
    std::execution::par, data.begin(), data.end(), 0LL,
    std::plus<>{}, [](int v) { return 1LL * v * v; });   // map + reduce

std::sort(std::execution::par_unseq, v.begin(), v.end(), std::greater<>{});
```

## Подводные камни

- **Исключение в параллельном алгоритме = `std::terminate`.** Стандарт требует
  завершать процесс при исключении из element-access-функции (кроме
  `bad_alloc`); распространение не гарантировано. Не полагайтесь на `try/catch`
  вокруг `par`-алгоритма — обрабатывайте ошибки иначе (флаг + `par` проверка).
- Гонки данные не прощает: тело должно быть **потокобезопасным**. Общий счётчик —
> `std::atomic` или `transform_reduce` (нейтральный элемент + `+`), а не обычный `int`.
- Не все алгоритмы можно векторизовать: `par_unseq` требует, чтобы функтор не
  делал блокировок и обращений к общей памяти.
- **Отсутствие бэкенда не ошибка**: код компилируется и работает, но
  последовательно — не делайте выводов о производительности по умолчанию.

## Задача

Вычислить сумму квадратов чисел 1..1000 через `transform`+`reduce` и
`transform_reduce`; посчитать чётные значения через `for_each` с `std::atomic`;
посчитать элементы `> 500` через `count_if`; отсортировать по убыванию
`par_unseq`. Вывести результаты.

## Где применяется

- Обработка больших массивов (численные расчёты, обработка изображений),
  агрегация данных, сортировки в компиляторах, ETL-конвейеры.

## Проверка

Вывод: `sum of squares 1..1000 = 333833500`, `transform_reduce sum = 333833500`,
`even count = 500`, `count > 500 = 500`, `sorted desc: front=100 back=1`,
`parallel stl done`. Код возврата `0` при совпадении, иначе `1`.

## Решение

См. `ex01_parallel_stl.cpp`. Обратите внимание на `_PSTL_PAR_BACKEND_TBB`:
на текущем тулчейне печатается «serial fallback (TBB net)».
