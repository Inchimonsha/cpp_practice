# m01_syntax/ex11_inheritance_polymorphism — Наследование и полиморфизм

> **Модуль:** `m01_syntax` · **Сложность:** ★★★★☆ · **Время:** 60–90 мин
> **Запуск:** `./run.ps1 m01_syntax/ex11_inheritance_polymorphism`

## Теория (кратко)

Наследование выражает «является» (`Circle` — это `Shape`) и включает
**динамический полиморфизм**: вызов `virtual`-функции через базовый указатель
попадает в реализацию производного класса. База с виртуальными функциями должна
иметь **виртуальный деструктор**. `override`/`final` ловят ошибки на этапе
компиляции. Абстрактный класс (чистые виртуальные функции) задаёт интерфейс.

| Ключевое слово | Смысл |
|---|---|
| `virtual` | участвует в динамической диспетчеризации |
| `override` | проверка, что метод реально переопределяет |
| `final` | запрет дальнейшего переопределения/наследования |
| `= 0` | чистая виртуальная (абстрактный класс) |
| `dynamic_cast` | безопасное приведение по иерархии (RTTI) |

## Синтаксис

```cpp
struct Shape {
    virtual ~Shape() = default;
    [[nodiscard]] virtual double area() const = 0;   // chistaya
    [[nodiscard]] virtual std::string_view name() const = 0;
};

struct Circle final : Shape {
    explicit Circle(double r) : r_(r) {}
    [[nodiscard]] double area() const override { return 3.14159 * r_ * r_; }
    [[nodiscard]] std::string_view name() const override { return "circle"; }
private:
    double r_{};
};
```

## Подводные камни

- Нет виртуального деструктора → `delete` через базовый указатель даёт UB.
- Вызов `virtual`-функции в конструкторе/деструкторе базового класса **не**
  попадает в производную (объект ещё/уже не производный).
- `dynamic_cast` требует RTTI и указателя/ссылки на полиморфный тип.
- Наследование ради переиспользования кода (а не «является») ведёт к хрупким
  иерархиям — предпочитайте композицию.

## Задача

В `ex11_inheritance_polymorphism.cpp`:

1. объявите абстрактный `Shape` с виртуальным деструктором;
2. реализуйте `Circle` и `Rect` с `override`;
3. сложите площади через вектор указателей на `Shape`;
4. используйте `dynamic_cast<Rect*>` для «узнавания» конкретного типа;
5. убедитесь, что виртуальный деструктор вызывается для каждого объекта.

## Где применяется

- Интерфейсы подсистем (рендер, ввод, аудио) с разными реализациями.
- Плагины: базовый интерфейс + динамически загружаемые классы.
- Полиморфные сущности в сценах/ресурсах (при осторожном использовании).
