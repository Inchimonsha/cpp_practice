## Теория (кратко)

`<functional>` даёт средства для работы с вызываемыми объектами:
`std::function` (стирание типа), `std::bind`/placeholders, `std::ref`,
готовые функторы (`plus`, `less`, `greater`). Современный стиль предпочитает
**лямбды** вместо `bind`, а `std::function` — на границах (хранение колбэков).

| Средство | Назначение |
|---|---|
| `std::function<Sig>` | хранит любой вызываемый с сигнатурой `Sig` |
| `std::bind` + `_1` | частичное применение (легаси) |
| `std::ref` / `reference_wrapper` | передать объект «по ссылке» в шаблон |
| функторы (`plus`, `greater`) | готовые операции |

## Синтаксис

```cpp
std::function<int(int)> square = [](int x) { return x * x; };

auto add10 = std::bind(std::plus<int>{}, std::placeholders::_1, 10);  // staroe

template <class F, class G>
auto compose(F f, G g) { return [f, g](auto x) { return f(g(x)); }; }

int value = 5;
auto ref = std::ref(value);  // reference_wrapper<int>
```

## Подводные камни

- `std::function` **копирует** захваченное состояние и добавляет косвенный
  вызов; на горячем пути лямбда/шаблон дешевле.
- `std::bind` легко даёт нечитаемый код (вложенные placeholders) — берите лямбды.
- `std::ref` нужен, когда фабрика/алгоритм копирует аргумент, а нам нужна ссылка
  (например, `std::thread`, `view`).
- Захват `this`/ссылок в `std::function`, пережившей объект, — висячие ссылки.

## Задача

В `ex10_functional.cpp`:

1. сохраните разные лямбды в `std::vector<std::pair<string, function<int(int)>>>`;
2. напишите `compose(f, g)` и примените к числу;
3. покажите `std::bind` (частичное применение) и сравните с лямбдой;
4. примените `std::ref` к переменной, меняемой функцией;
5. используйте функторы `std::plus`/`std::greater` напрямую.

## Где применяется
