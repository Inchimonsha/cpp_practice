# m04_stl/ex07_allocators_pmr — Аллокаторы и `std::pmr`

> **Модуль:** `m04_stl` · **Сложность:** ★★★★☆ · **Время:** 50–70 мин
> **Запуск:** `./run.ps1 m04_stl/ex07_allocators_pmr`

## Теория (кратко)

**Аллокатор** отделяет стратегию выделения памяти от контейнера. `std::pmr`
(Polymorphic Memory Resource, C++17) задаёт стратегию **в рантайме** через
`memory_resource`, что позволяет применять арены и пулы без смены типа
контейнера (используется `pmr::`-синоним, например `pmr::vector<T>`).

| Ресурс | Стратегия |
|---|---|
| `new_delete_resource()` | глобальный `new`/`delete` |
| `monotonic_buffer_resource` | арена: выделяет вперёд, освобождает всё сразу |
| `unsynchronized_pool_resource` | пул блоков фиксированных размеров |

## Синтаксис

```cpp
std::array<std::byte, 4096> buffer{};
std::pmr::monotonic_buffer_resource arena{buffer.data(), buffer.size()};

std::pmr::vector<int> v{&arena};     // pamyat' iz areny
std::pmr::string s{"text", &arena};

std::pmr::unsynchronized_pool_resource pool;
std::pmr::vector<std::pmr::string> lines{&pool};
```

## Подводные камни

- `monotonic_buffer_resource` **не освобождает** отдельные объекты: арена
  сбрасывается целиком (`release()` или разрушение). Это идеально для
  «на кадр», но не для долгоживущих структур.
- Тип `pmr::vector<T>` отличается от `std::vector<T>` — при передаче между
  подсистемами учитывайте несовместимость типов.
- Ссылки на данные из арены становятся недействительны после её сброса.
- `unsynchronized_pool_resource` не потокобезопасен.

## Задача

В `ex07_allocators_pmr.cpp`:

1. создайте `pmr::vector<int>` на `monotonic_buffer_resource` над стековым
   буфером;
2. добавьте элементы и выведите размер/ёмкость;
3. заведите `pmr::string` и `pmr::vector<pmr::string>` на пуле;
4. покажите `release()` и повторное использование арены;
5. сравните с `new_delete_resource` (поведение по умолчанию).

## Где применяется

- Кадровые аллокаторы в играх (всё освобождается в конце кадра).
- Парсеры/сериализация: множество мелких объектов живут ограниченное время.
- Пулы для объектов фиксированного размера (компоненты ECS, события).

## Проверка

Прогон печатает размеры/ёмкости и содержимое из арены и пула; завершается `0`.
