# m04_stl/ex01_sequence_containers — Последовательные контейнеры

> **Модуль:** `m04_stl` · **Сложность:** ★★★☆☆ · **Время:** 50–70 мин
> **Запуск:** `./run.ps1 m04_stl/ex01_sequence_containers`

## Теория (кратко)

Последовательные контейнеры хранят элементы по порядку, но с разной стоимостью
операций. Выбор контейнера — это выбор компромисса между произвольным доступом,
вставкой/удалением и локальностью памяти.

| Контейнер | Доступ | Вставка в начало | Вставка в конец | Память |
|---|---|---|---|---|
| `vector` | O(1) | O(n) | O(1) амортизир. | непрерывная |
| `deque` | O(1) | O(1) амортизир. | O(1) амортизир. | блоками |
| `list` | O(n) | O(1) | O(1) | узлы, 2 связи |
| `forward_list` | O(n) | O(1) | — | узлы, 1 связь |

`vector` растёт по **capacity**: при переполнении выделяется больший буфер и
элементы **перемещаются**. `reserve` заранее устраняет лишние реаллокации.

## Синтаксис

```cpp
std::vector<int> v;
v.reserve(100);                  // bez reallokacij do 100 elementov
v.push_back(1);
v.emplace_back(2);               // konstruktor na meste

std::deque<int> d;
d.push_front(0); d.push_back(1);

std::list<int> l{3, 1, 2};
l.sort();
l.remove_if([](int x) { return x % 2 == 0; });

std::forward_list<int> f;
f.push_front(1);
```

## Подводные камни

- `vector::push_back` может инвалидировать **все** итераторы/ссылки (реаллокация).
- `deque` не даёт непрерывного буфера: `data()` нет.
- `list`/`forward_list` кэш-недружелюбны; на практике `vector` чаще быстрее.
- `forward_list` не имеет `size()` в классической реализации (только
  `std::distance`), вставка перед элементом требует «итератора на предыдущий».

## Задача

В `ex01_sequence_containers.cpp`:

1. покажите рост `capacity` `vector` при `push_back` и эффект `reserve`;
2. продемонстрируйте `deque` (`push_front`/`push_back`);
3. для `list` примените `sort` и `remove_if`;
4. для `forward_list` — вставку/удаление с использованием `before_begin`;
5. выведите итоговые размеры (инварианты, а не внутреннюю ёмкость).

## Где применяется

- `vector` — универсальный выбор: компоненты ECS, буферы, пулы.
- `deque` — очереди с доступом с обоих концов, BFS-очереди.
- `list` — частые вставки/удаления в середине при неизменных итераторах.
