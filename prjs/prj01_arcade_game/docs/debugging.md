# Стратегия отладки: Arcade Game

## Инструменты

- логгер `cpp_course::log` (уровни trace..error), Debug-сборка;
- отладчик (GDB/lldb/VS) для пошагового прохода;
- `assert` / `CPP_COURSE_CHECK` в тестах для инвариантов модели.

## Типичные баги проекта и как их ловить

| Симптом | Причина | Диагностика |
|---|---|---|
| «газ на FPS» | движение без `dt` | сравнить 30 vs 120 FPS |
| пролёт сквозь предмет | коллизия по «телепорту» | проверка `speed*dt` |
| рекорд не сохраняется | путь от cwd | путь от каталога exe |
| висит при `Esc` | не обработан `Closed` | проход по событиям |
| объект бесконечно спавнится | нет границы нижней удаления | лог-поток спавна |

## Процедура

1. Воспроизвести в минимальном сценарии.
2. Добавить лог-строки (`log::debug`) или брейкпоинт.
3. Исправить; добавить регрессионный тест в `tests/`.

## Полезные лог-точки (trace)

- спавн/удаление объекта;
- коллизии платформа↔предмет;
- смена `GameState`;
- загрузка/сохранение рекорда (результат операции).
