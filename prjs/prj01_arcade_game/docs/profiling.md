# Стратегия профилирования: Arcade Game

## Порядок (от простого к сложному)

1. **FPS/время кадра** — уже есть в ex01 (`FpsCounter`). Если игра стабильно
   ≥ 120 FPS на целевой машине — профилирование не нужно.
2. **Секция `dt`** — раздельно мерить время события/обновления/рендера (лог).
3. **Внешний профайлер** — после th50 (`perf`, VTune, etc.), только если пункты
   1–2 указали на горячую точку.

## Watch-лист

- большое количество объектов (`std::vector<FallingObject>` без экономии) —
  «поедание» кэша на сотнях тысяч объектов; не наша цель;
- пересоздание строк в заголовке/тексте каждый кадр (выполнять аккуратно,
  не чаще 2–4 раз в секунду);
- копирование Aabb-структур по значению в горячем цикле — смотреть передачу.

## Регламент

Профилирование — только при симптоме (FPS падает, лаги). Не преждевременно
(«профилируй то, что медленно, а не то, что можно оптимизировать»).
