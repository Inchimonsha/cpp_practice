# prjs/

Пет-проекты курса. Именование: `prjNN_project_name` (пример:
`prj01_arcade_game`).

## Обязательный состав каждого проекта

```
prjNN_project/
├── README.md          ← обзор, команды сборки и запуска
├── brief.md           ← постановка: жанр, цель, проблема, что изучается (разделы 1–8)
├── requirements.md    ← требования: функц./нефункц., ограничения, MVP, vertical slice (9–17)
├── milestones.md      ← вехи и декомпозиция задач (22–23)
├── architecture.md    ← архитектура, подсистемы, модель данных, жизненный цикл (18–34, ключевое)
├── design/            ← геймдизайн: концепт, экраны, списки ассетов
├── docs/              ← стратегии тестирования/отладки/профилирования/сохранений, code review
├── src/               ← реализация (.cpp)
├── include/           ← публичные заголовки проекта (.hpp)
├── assets/            ← ассеты проекта (или README с инструкцией)
├── tests/             ← тесты
├── CMakeLists.txt     ← сборка проекта
└── CHANGELOG.md       ← журнал изменений проекта
```

Шаблон — в `tools/templates/project/`.

## Обязательные пункты постановки (в сумме по файлам проекта)

См. требование «Каждый проект обязан содержать» — 34 пункта распределены между
`brief.md`, `requirements.md`, `architecture.md`, `milestones.md`, `docs/` и
`README.md`. Файлы не должны противоречить друг другу.

## Стадии разработки проекта

1. **Каркас** — собираемый скелет, пустые циклы и заглушки.
2. **Vertical slice** — сквозной минимальный сценарий игры до конца.
3. **Дополнительные возможности** — расширения по списку.
4. **Полировка и упаковка** — критерии завершения.

## Правила

- Каждый проект собирается отдельно (`CMakeLists.txt`) и подключается корнем.
- Каждый последующий проект добавляет новые архитектурные проблемы (см.
  `ROADMAP.md`, раздел 6).
- Реализация больших проектов начинается с vertical slice, а не с полного
  функционала.
