# ROADMAP — план учебного курса

План курса «C++ и Lua: разработка 2D-игр и игровых песочниц (SFML)».
Актуальный статус каждого раздела — в `CHECKLIST.md`, изменения — в `CHANGELOG.md`.

---

## 1. Принципы построения курса

1. **От простого к сложному.** Каждый раздел опирается только на ранее изученное.
2. **Теория → практика → проект.** Каждому модулю соответствует блок тем
   (`thXX`), затем задания (`exXX`), затем проекты (`prjXX`).
3. **Всё проверяется.** Примеры компилируются, тесты выполняются, ссылки и
   структура проверяются валидаторами.
4. **Никаких пустых разделов.** Раздел считается готовым, только когда содержит
   все обязательные файлы.
5. **Реалистичные проекты.** Проекты приближены к реальной разработке: у каждого
   есть постановка, требования, milestones, архитектура, тесты и changelog.

## 2. Модули и зависимости

Зависимость `A → B` означает: модуль/раздел `B` требует знаний из `A`.

```
M0 (setup) ──▶ M1 (C++) ──▶ M3 (математика) ──▶ M4 (SFML) ──▶ M5 (архитектура)
   │              │            │                   │              │
   │              ▼            ▼                   ▼              ▼
   │           M2 (Lua) ──▶ [M4 использует M1]  M6 (2D GameDev)──┼─▶ M8 (процесс)
   │              │            │                   │              │
   │              └───────────▶└───────────────────┤              ▼
   │                                               ▼           M9 (перфоманс)
   └──── M10 (финальные проекты prj01–prj07) ◀──────────────┘
```

Ключевые правила:

- `M4 (SFML)` требует `M1` (C++ — классы, RAII, контейнеры) и минимума `M3`
  (векторы, коллизии).
- `M5 (архитектура)` требует `M1`, `M3`, `M4`.
- `M6 (2D GameDev)` требует `M5`.
- `M7 (песочницы)` требует `M5` + `M3` (процедурная генерация); по умолчанию
  идёт после `M6`, но может изучаться параллельно с ним.
- `M2 (Lua)` — обязателен к `M7` (моддинг) и `prj05`/`prj07`, желателен к `M6`.
- `M8` и `M9` — сквозные: их элементы применяются во всех проектах, но как
  самостоятельные блоки идут после `M5`.

## 6. Проекты

### Развитие сложности

```
prj01 arcade ──▶ prj02 top-down ──▶ prj03 platformer
                                       │
prj06 engine ◀─────────────────────────┴───────▶ prj04 sandbox
                                       │           │
                                       └─────▶ prj05 lua-scripted ──▶ prj07 capstone
```

Каждый следующий проект добавляет новые инженерные проблемы (не переименовывает
сущности предыдущего):

- **prj01** — игровой цикл, ввод, коллизии, очки, UI, звук, сохранение рекорда.
- **prj02** — карта, камера, NPC, диалоги, квесты, инвентарь, сохранения.
- **prj03** — платформерная физика, прыжки, анимации, уровни, checkpoints.
- **prj04** — процедурный мир, чанки, крафт, день/ночь, оптимизация.
- **prj05** — C++ engine + Lua-логика, modding API, изоляция скриптов.
- **prj06** — мини-движок: сцены, ресурсы, ECS, event bus, сериализация, debug overlay.
- **prj07** — финальный: C++ + Lua + ECS + процедурная генерация + упаковка.

Детальные постановки лежат в `prjs/prjNN_*/brief.md` и `requirements.md`.

## 7. Критерии завершения курса

1. Все разделы `theory/` содержат обязательные файлы (проверка валидатором).
2. Все примеры компилируются, все тесты заданий и проектов проходят.
3. Валидаторы `check_structure.py` и `check_links.py` не выдают ошибок.
4. `prj01`–`prj07` воспроизводят заявленные milestones (vertical slice + расширения).
5. `CHECKLIST.md` полностью отмечен, `CHANGELOG.md` актуален.

## 8. Известные риски и ограничения

- SFML-зависимые цели собираются только при наличии пребилта SFML под вашу
  платформу; на Windows требуется UCRT-тулчейн (MSYS2 `ucrt64` / winlibs UCRT,
  GCC ≥ 14) — msvcrt-тулчейн линкует, но оконные приложения падают при запуске
  (кросс-CRT heap-коррупция; диагностика в `th01`).
- Аудио-тесты требуют звукового устройства; в CI они помечены как
  опциональные.
- Unix-сборки проверялись только на GNU/Linux; точная эквивалентность команд
  для macOS не гарантируется (инструкции помечены).
